# 사일로 전개도 기반 반자율 전면점검 — 구현 명세

안전감시 다음 핵심 기능. 사용자가 사일로 또는 점검 영역의 크기를 입력하면 카메라 점검 폭과
중첩률을 반영해 전체 표면을 덮는 경로를 생성하고, 좌·우 모터 엔코더와 IMU 자이로를 이용해 경로를
추종한다. 안전 이상이 발생하면 경로를 일시정지하고 정지 래치를 건 뒤, 사용자 확인 후 중단 지점부터
재개한다.

**코드 계약(노드·토픽·메시지 타입)은 [[3. 소프트웨어/07. 구현 계약 — 노드·토픽·메시지 정본]].**

관련 정본: [[3. 소프트웨어/04. 센서-안전감시 구현명세]] · [[3. 소프트웨어/01. STM32]] ·
[[3. 소프트웨어/02. 젯슨]] · [[3. 소프트웨어/03. 대시보드]]

## 0. 이번 범위 (2026-08-19 사용자 확정)

**"모터가 실제로 도는 것까지"가 이번 목표다.** 경로를 만들고, 오도메트리로 위치를 추정하고,
추종 로직이 `/silorobot/drive_command`를 내서 **모터가 그 명령대로 도는 것**까지 증명하면 완료로
본다.

이번에 요구하지 않는 것:

- 벽면 전면 커버리지 완주
- 오도메트리 정밀도 수치 목표 (누적오차 몇 % 이내 같은 주장)
- 엔코더 보정의 통계적 엄밀성 — 대략값으로 시작하고, 실주행이 가능해지면 §7 절차로 다시 잡는다

조립이 늦어 실주행이 불가능하면 **§18 HIL 대체 시연**이 이번 범위의 완료 형태가 된다.
아래 §1~§17은 최종 목표 기준 설계이므로, 구현자는 이 절의 범위를 넘겨 만들지 않는다.

## 1. 기능 정의

```text
사일로 지름·높이·점검폭·중첩률 입력
→ 원통형 사일로를 2D 전개도로 변환
→ 세로/가로 지그재그 경로 후보 생성
→ 예상 이동거리·회전횟수 비용 비교
→ 효율 경로 선택
→ 엔코더 오도메트리 + IMU 자이로 보정으로 추종
→ 점검 완료 영역 실시간 표시
→ 안전 이상 시 PAUSED_SAFETY + 모터 정지
→ 사용자 확인 후 중단 지점부터 재개
```

대외 표현은 `최적 경로`보다 **이동거리와 회전 횟수를 비교한 효율 경로** 또는 **커버리지 경로**를
사용한다. 전역 최적임을 수학적으로 증명하지 않은 상태에서 `최적`이라고 단정하지 않는다.

## 2. 현재 하드웨어로 가능한 이유와 한계

### 사용 가능

- 좌측 앞 M1과 우측 앞 M3에 AB 2상 증분형 엔코더 존재
- 모터축 기준 16PPR, 감속비 1/290, 3.3V/5V 출력 지원
- 좌·우 한 개씩이므로 차동궤도 오도메트리 구성 가능
- STM32가 실시간 카운트와 모터 출력을 담당할 수 있음
- Nano B01이 경로계획·위치추정·경로추종을 담당할 연산량은 충분
- WT901C 자이로로 단시간 회전량 보정 가능

### 반드시 실측

- 엔코더 A/B 핀과 좌·우 부호
- x1/x2/x4 중 실제 카운트 방식
- 출력축 1회전당 실제 카운트 — `16PPR × 290 × 4`를 문서만 보고 확정하지 않음
- 궤도 1회전당 이동거리와 엔코더 count/mm
- 좌·우 궤도 중심 간 거리(track width)
- 평면·철판에서 직진 1m 오차와 제자리회전 오차

### 한계

- 자력 궤도는 철판에서 미끄러질 수 있어 엔코더 이동량과 실제 이동량이 달라질 수 있음
- WT901C 자력계는 할바흐 자석·모터·철판의 영향을 크게 받을 수 있어 절대 Yaw 정본으로 사용 금지
- 1차는 엔코더 오도메트리 주체 + IMU 자이로 단기 보정. 자력계는 실측이 안정적인 경우에만 낮은 가중치
- 슬립이 큰 환경의 장거리 전역 위치정확도는 카메라 마커·비전 오도메트리 등 추가 보정 없이 보장하지 않음

연산량은 병목이 아니다. **핀 배정·카운트 보정·궤도 슬립·제어기 튜닝이 실제 병목**이다.

## 3. 모드

| 모드 | 기능 | 보고서 표현 |
|---|---|---|
| `MANUAL` | 기존 터치 전후진·조향 | 원격 수동 주행 |
| `ASSISTED` | 경로 자동 생성, 다음 구간 안내, 사용자가 주행 | 반자율 점검 안내 |
| `AUTO` | 엔코더·자이로 기반 경로 자동 추종 | 실물 반복시험 완료 후만 반자율 경로 추종 완료 |

자동추종이 미검증이면 `AUTO` 버튼을 숨기거나 `실험 기능`으로 표시한다.

## 4. 좌표계

### 사일로 전개도

원통형 측면을 펼친 직사각형 좌표를 사용한다.

```text
width  = circumference = π × diameter
height = inspection_height
x      = 원주 방향 거리
y      = 수직 방향 거리
theta  = 전개도 평면에서 로봇 진행 방향
```

- 단위는 내부 계산에서 m로 통일
- 시작점은 좌하단 `(0,0)`을 기본값으로 하되 네 모서리 중 선택 가능
- 내부·외부 점검은 좌표계는 같고 카메라/자석 방향만 장착 조건에 따라 달라짐
- 천장·바닥은 원통 측면과 별도 surface id로 관리; 하나의 평면 오도메트리로 억지 연결하지 않음

### 직사각형 시험판

실기 1차는 사일로 전체 대신 폭 `W`, 높이 `H`인 직사각형 철판 또는 바닥 시험 영역으로 검증한다.
동일 알고리즘에서 `width=W`, `height=H`만 사용한다.

## 5. 경로계획 입력

```json
{
  "surface": "CYLINDER_SIDE",
  "diameter_m": 10.0,
  "width_m": null,
  "height_m": 15.0,
  "scan_width_m": 0.30,
  "overlap_ratio": 0.20,
  "safety_margin_m": 0.10,
  "start_corner": "BOTTOM_LEFT",
  "preferred_finish": null,
  "max_speed_mps": 0.05,
  "turn_weight_m": 0.30
}
```

- 원통 측면이면 `width=πD`
- 직사각형이면 `width_m` 직접 입력
- `scan_width_m`는 현재 카메라·벽면거리에서 실제로 유효하게 검사되는 폭
- `overlap_ratio`는 0 이상 1 미만
- 경로 간격 `spacing = scan_width × (1-overlap)`
- 카메라 점검 폭을 실측하지 않았다면 사용자가 직접 입력하고 보고서에 예상값으로 구분

## 6. 커버리지 경로 생성

1차는 직사각형 영역의 Boustrophedon, 즉 잔디깎기형 지그재그 경로를 사용한다.

### 후보 A — 수직 스트라이프

```text
stripe_count = ceil((width - 2×margin) / spacing)
주행: 아래→위, 옆 이동, 위→아래 반복
```

### 후보 B — 수평 스트라이프

```text
stripe_count = ceil((height - 2×margin) / spacing)
주행: 좌→우, 옆 이동, 우→좌 반복
```

### 비용

```text
cost = total_path_length
     + turn_weight × turn_count
     + optional_finish_penalty
```

- A와 B의 비용을 모두 계산해 낮은 경로 추천
- 추천 결과와 두 후보 비용을 UI에 같이 표시해 선택 근거 제공
- 원통 측면은 x=0과 x=둘레가 이어지는 seam을 고려하되 1차는 seam을 한 번만 넘도록 경로 생성
- 장애물 회피는 2차 기능. 1차 경로에 장애물이 없다고 가정하고 UI에 명시

### 출력

```json
{
  "plan_id": "20260821-001",
  "planner": "RECTANGULAR_BOUSTROPHEDON_V1",
  "orientation": "VERTICAL",
  "estimated_length_m": 0.0,
  "turn_count": 0,
  "coverage_ratio": 1.0,
  "waypoints": [
    {"x":0.1,"y":0.1,"theta":1.5708,"action":"START"},
    {"x":0.1,"y":1.9,"theta":1.5708,"action":"DRIVE"}
  ]
}
```

## 7. 엔코더 입력 구현

### 핀 배정 전 확인

- 현재 PWM은 TIM2/3/4를 사용하므로 타이머 충돌 금지
- F401RE와 F411RE 모두에서 실제 노출된 핀인지 확인
- CubeMX 또는 데이터시트 AF 매핑으로 두 개의 encoder-mode timer 사용 가능 여부 우선 검토
- 타이머 두 개가 어렵다면 네 GPIO EXTI로 AB 상태 전이표를 구현
- 최종 핀은 [[3. 소프트웨어/01. STM32]]와 `docs/pinmap.md`에 동시에 반영

### 카운터

- 좌·우 누적 카운트는 signed int32
- 20Hz 텔레메트리와 무관하게 인터럽트/타이머 카운트는 지속
- 비정상 AB 전이 카운터를 별도로 두어 배선·노이즈 확인
- STM32 재부팅 시 누적값 0으로 초기화하고 Nano가 odom reset 이벤트 처리

### 실측 보정

```text
meters_per_count_left  = 실제 좌측 이동거리 / 좌측 count
meters_per_count_right = 실제 우측 이동거리 / 우측 count
track_width_m          = 좌우 궤도 중심 간 거리
```

- 바닥 직진 1m를 최소 5회 반복해 좌·우 각각 보정
- 제자리 360° 회전을 최소 5회 반복해 track width 유효값 보정
- 이론 감속비 계산값보다 실측 count/m를 정본으로 사용

## 8. STM32→Nano 오도메트리 프레임

기존 거리 8바이트 프레임은 유지하고 별도의 누적 엔코더 프레임을 추가한다. 누적값을 사용하면 프레임
하나가 손실돼도 다음 프레임에서 복구할 수 있다.

```text
[0xBC][0x02][left_count_i32_le][right_count_i32_le][flags][checksum][0x55]
```

총 13바이트:

| 바이트 | 내용 |
|---:|---|
| 0 | `0xBC` encoder header |
| 1 | `0x02` type |
| 2~5 | left signed int32 little-endian |
| 6~9 | right signed int32 little-endian |
| 10 | flags |
| 11 | byte 1~10 XOR |
| 12 | `0x55` end |

초기 flags 후보:

- bit0: left encoder signal valid
- bit1: right encoder signal valid
- bit2: invalid transition seen
- bit3: odom reset since last connection
- 나머지 예약

거리 프레임과 엔코더 프레임을 각각 20Hz 송신하되 UART 부하를 계산하고, 파서는 header별 고정길이로
분리한다. 이 프레임은 새 결정이므로 코드 구현 시 양쪽 계약시험을 반드시 추가한다.

## 9. 오도메트리

좌·우 이동거리:

```text
dl = delta_left_count  × meters_per_count_left
dr = delta_right_count × meters_per_count_right
ds = (dl + dr) / 2
dtheta_encoder = (dr - dl) / track_width
```

pose 적분:

```text
x += ds × cos(theta + dtheta/2)
y += ds × sin(theta + dtheta/2)
theta = normalize(theta + dtheta)
```

### IMU 결합

- 엔코더 기반 `dtheta_encoder`가 기본
- IMU 자이로의 적분 회전량을 짧은 구간 보조값으로 사용
- 자력계 기반 절대 Yaw는 자석·철판 환경에서 별도 검증 전 사용 금지
- 1차는 가중 평균 또는 complementary filter
- EKF는 시간이 남을 때만; 필터 이름보다 반복시험 오차가 중요

예시 구조:

```text
dtheta = alpha × dtheta_encoder + (1-alpha) × dtheta_gyro
```

`alpha`는 실측으로 정한다. IMU timestamp와 encoder timestamp가 크게 어긋나면 융합하지 않는다.

## 10. 경로 추종

1차는 저속 waypoint 추종 또는 Pure Pursuit를 사용한다.

### 권장 순서

1. 직진 거리 폐루프
2. 제자리 지정각 회전 폐루프
3. 직진+회전 세그먼트 상태머신
4. Pure Pursuit로 부드러운 연속 추종

시간 기반 `3초 전진`, `1초 회전`은 자율 경로 추종으로 인정하지 않는다.

### 제어 출력

```text
linear velocity v
angular velocity w
→ throttle / turn 변환
→ 기존 Nano drive_command
→ 기존 STM32 아케이드 믹싱
```

- 최대속도·가속도·회전속도 제한
- waypoint 도달 반경과 heading 허용오차 설정
- 적분항 windup 방지
- 안전감시 STOPPED이면 경로추종 출력보다 STOP이 항상 우선

## 11. 반자율 상태머신

| 상태 | 의미 |
|---|---|
| `IDLE` | 계획 없음 |
| `READY` | 계획 생성, 시작 대기 |
| `RUNNING` | 경로 추종 중 |
| `PAUSED_USER` | 사용자 일시정지 |
| `PAUSED_SAFETY` | 안전감시가 정지시킴 |
| `RECOVERY_REQUIRED` | pose·센서 확인 필요 |
| `COMPLETE` | 전체 경로 완료 |
| `ERROR` | encoder/IMU/STM32 오류 |

### 안전 연동

```text
RUNNING + safety WARNING → 속도 유지 여부는 1차 실측 후 결정, UI 경고
RUNNING + safety STOPPED → PAUSED_SAFETY + STOP
PAUSED_SAFETY + 조건 정상 → 그대로 대기
사용자 release → pose 확인 → READY
사용자 resume → 중단 waypoint부터 RUNNING
```

안전 해제와 경로 재개는 별도 버튼으로 둔다. 정지 해제와 동시에 자동으로 움직이면 위험하다.

```json
{
  "autonomy": {

    "total_waypoints": 20,
    "coverage_ratio": 0.16,
```

```json
{"type":"route_start","plan_id":"20260821-001"}
{"type":"route_pause"}
```

모든 명령은 현재 상태에서 허용되는지 Nano가 검증한다.

## 13. RPi4 화면

### 계획 화면

- 사일로 지름 또는 영역 폭·높이
- 점검폭·중첩률·안전여백
- 시작 모서리
- 세로/가로 후보의 예상 거리·회전수 비교
- `추천 경로 생성` 버튼

### 실행 화면

- 2D 전개도와 경로선

## 18. 최종 조립 불가 시 HIL 대체 시연

차체가 조립되지 않아도 경로계획과 물리 구동계의 폐루프는 검증할 수 있다. 화면 애니메이션만 돌리는
것이 아니라 **실제 STM32·모터·엔코더를 제어 루프에 포함한 Hardware-in-the-Loop 방식**으로 구성한다.

```text
사일로 크기 입력
→ 커버리지 경로 생성
→ Nano 경로추종기가 실제 STM32에 모터 명령
→ 좌·우 실제 모터·바퀴 회전
→ 실제 엔코더 누적 카운트가 Nano로 귀환
→ 오도메트리 계산
→ 화면의 가상 로봇/CAD pose가 실제 카운트에 따라 이동
→ waypoint 도달 시 다음 직진·회전 구간으로 전환
```

### 물리 구성

- 좌·우를 대표하는 엔코더 모터 M1·M3를 최소 구성으로 사용하고 가능하면 모터 4개 전체 연결
- 회전이 잘 보이도록 바퀴 또는 임시 원판을 장착하고 좌·우에 다른 색 테이프 표시
- 모터·엔코더·STM32·Nano·RPi4가 한 프레임에 보이도록 배치
- 바퀴가 테이블을 밀지 않도록 단단한 지그에 고정하고 손·배선이 회전체에 닿지 않게 함
- 무부하 시험임을 화면과 보고서에 표시

### 화면 구성

```text
좌측 45%: 최종 목표 형상 CAD + 사일로 전개도 경로
우측 35%: 실제 모터·바퀴·STM32 벤치 영상
하단 20%: L/R encoder count, 가상 pose, 현재 waypoint, AUTO 상태
```

- CAD에는 `최종 목표 형상(CAD)` 고정 자막
- 실물에는 `구동계 HIL 벤치 — 무부하` 고정 자막
- 가상 pose에는 `실제 엔코더 기반 시뮬레이션 위치` 고정 자막
- 사전 제작된 애니메이션이 아니라 실제 encoder count가 멈추면 화면 pose도 멈춰야 함

### 영상에서 증명할 동작

1. 경로 생성 직후 모터 정지 상태
2. START 후 직진 구간 — 좌·우 같은 방향, count 증가, 가상 pose 직진
3. 회전 구간 — 좌·우 차동 회전, theta 변화
4. 다음 스트라이프 진입 — waypoint 자동 증가
5. 바퀴 또는 엔코더 입력을 멈추면 해당 pose 진행도 멈춤
6. 안전 이상 모사 — STOPPED·모터 정지·경로 PAUSED_SAFETY
7. 조건 복구·안전 해제 후에도 대기, 별도 RESUME 후 재진행

### 허용 표현

- `사일로 규격 기반 커버리지 경로 자동 생성`
- `실제 모터·엔코더를 포함한 반자율 제어 HIL 검증`
- `엔코더 피드백 기반 가상 오도메트리·waypoint 전환 확인`
- `최종 프레임 조립 대기 / 무부하 구동계 시험`

### 금지 표현

- `실물 자율주행 성공`
- `실제 위치 오차 검증 완료`
- `벽면 경로 추종 완료`
- `사일로 전면점검 완료`
- 무부하 count 기반 pose를 실제 이동거리 실측값처럼 제시

HIL 결과는 경로계획·명령·모터·엔코더·오도메트리·상태전이의 소프트웨어/전장 폐루프를 증명한다.
차체 운동학·궤도 슬립·부하·벽면 부착 성능은 최종 조립 후 별도 시험한다.

안전 이상은 현재 모터가 장착된 프로파일에 통제된 흔들림·한쪽 들림·전체 이격 외란을 주어 모사한다.
구체적인 지그·시험·촬영·안전 기준은 [[3. 소프트웨어/04. 센서-안전감시 구현명세#18. 프로파일 장착
상태의 외란 모사 시험]]을 따른다.

## 19. 점검 증거기록

점검 로봇의 결과물이 단순 실시간 영상에 그치지 않도록, 운용자 수동 기록과 안전 사건 기록을 같은
형식으로 저장한다.

### 수동 기록 흐름

```text
운용자가 실시간 영상에서 이상 확인
→ RPi4 `점검 기록` 버튼
→ 현재 CSI 프레임 저장 요청
→ 동일 record_id로 이미지 + JSONL 메타데이터 저장
→ 화면에 `점검 기록 저장 완료` 카드 표시
```

### 최소 메타데이터

```json
{
  "record_id": "20260821-154218-004",
  "time": "2026-08-21T15:42:18.120+09:00",
  "trigger": "OPERATOR",
  "image": "records/2026-08-21/20260821-154218-004.jpg",
  "plan_id": "20260821-001",
  "waypoint": 3,
  "pose_source": "ENCODER_HIL",
  "pose": {"x":0.2,"y":0.8,"theta":1.57},
  "imu": {"roll":91.2,"pitch":2.1,"yaw":14.0},
  "distance": [48,51,49],
  "safety_state": "NORMAL",
  "note": ""
}
```

- 조립 전 pose는 `ENCODER_HIL`, 실물 경로 보정 후 `ODOMETRY`로 구분
- 이미지 저장 실패 시 JSONL에 `image:null`과 오류 사유 기록; 성공한 것처럼 UI 표시 금지
- 안전정지 이벤트는 `trigger:"SAFETY_STOP"`으로 같은 형식에 reason·동적 센서값 추가
- AI 완료 후 `trigger:"AI_DETECTION"`, detection class·confidence·bbox를 같은 record에 추가
- 이미지와 JSONL은 record id로 연결하고 날짜별 폴더에 저장

### 구현 위치

- 1차 권장: RPi4가 화면에 수신 중인 실제 영상 프레임을 캡처하고 메타데이터를 함께 저장
- 현재 영상 파이프라인에서 안전한 프레임 캡처가 어렵다면 Nano RTSP/GStreamer에 tee·snapshot 경로 추가
- 어느 쪽이든 demo 이미지·사전 저장 이미지를 실제 점검기록처럼 사용하지 않음

### 완료 조건

- 실제 CSI 피사체를 바꿔 기록 버튼을 3회 누르면 서로 다른 이미지 3장 생성
- 각 이미지와 JSONL의 record id·시각·센서값이 일치
- RPi4 화면에서 가장 최근 기록의 썸네일·시각·상태 확인
- 안전정지 1회가 별도 사건 record로 저장
- 영상 촬영 시 저장 버튼→카드 생성→실제 파일 확인을 연속으로 제시
