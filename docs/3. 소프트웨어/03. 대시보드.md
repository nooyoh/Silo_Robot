# 대시보드

> 2026-08-19 목·금 센서 기능개발은 [[3. 소프트웨어/04. 센서-안전감시 구현명세]]를 정본으로 사용.
> RPi4는 센서·안전상태 표시와 해제 요청을 담당하며 안전판정의 유일한 주체가 아니다.
> 반자율 주행 UI·사일로 전개도·경로 진행 표시는 [[3. 소프트웨어/05. 반자율 전면점검 구현명세]]를 따른다.

라즈베리파이4 + 터치스크린 기반. 원격 모니터링과 로봇 제어를 동시에 담당한다.

## 구성
- 라즈베리파이4 + 7인치 공식 터치스크린 (LCD 터치스크린 케이스 포함, [[05. 부품표]])
- 기능: 원격 모니터링 + 터치스크린을 통한 로봇 제어 — 1차로는 둘 다 최소 기능만 구현

## 스펙
- OS: Raspberry Pi OS (64-bit, Debian 13 Trixie, Desktop)
- hostname: `amc` / 사용자: `amc71`
- 이전(2026-08-14 이전) 학습용으로 쓰던 OS는 백업 후 완전히 재설치함 — 이전 설정은 승계하지 않음
- 앱 스택: C++ + Qt6, RPi4 자체 native 빌드 — 영상 실시간 표시 성능 확보 목적 ([[02. 결정로그]])
- 로봇(Jetson Nano B01) ↔ 대시보드 통신: 무선, Tailscale로 동일 네트워크 구성 후 통신
  ([[02. 결정로그]])
- 영상 스트리밍(Jetson → RPi4): RTSP (GStreamer 기반), Qt 수신 측도 GStreamer 연동
- 제어·상태 데이터(배터리/IMU/거리센서/이동명령 등, 영상 제외): WebSocket —
  **대시보드가 WebSocket 서버**, Nano B01과 Orin Nano Super가 클라이언트로 접속
  ([[02. 결정로그]]). 전원 켜는 순서와 무관하게 붙고, 오린→대시보드 연결이 로봇을 경유하지
  않아도 되기 때문. 단 **영상(RTSP)은 반대로 Nano B01이 서버**이고 대시보드가 클라이언트다.
  <!-- "서버"의 두 가지 뜻(연산 역할 = Orin / 접속 대기 = 대시보드) 구분은
       [[01. README]] 시스템 구성 절 참조. 대시보드는 WS 서버일 뿐 두뇌가 아님 -->
- 결함탐지 결과: 오린 나노 Super가 박스 좌표(+종류·신뢰도 등)를 WebSocket으로 전송, Qt가 RTSP
  영상 위에 실시간 오버레이로 그림. 재인코딩된 영상 대신 좌표만 전송 ([[02. 결정로그]])
- 터치스크린: 7인치 공식 터치스크린 + 케이스 (디바이스마트 상품번호 12509770, [[05. 부품표]]) —
  양손으로 케이스를 잡고 좌우 엄지로 조작하는 것을 전제로 화면 설계

### 화면 레이아웃 (1차, 최소 기능)
- 중앙: 영상(RTSP 스트림)을 크게 표시, 주변/하단에 상태 정보 — 배터리 잔량, IMU(자세·속도),
  거리센서 3점, 로봇 연결 상태(Tailscale 연결 여부)
- 왼쪽 엄지 영역: 이동 제어 — 아케이드 스타일 2분할. 한쪽 축은 전진/후진, 다른 축은 좌/우 회전
  (궤도 2모터 독립구동 특성상 직관적)
- 오른쪽 엄지 영역: 정지(비상정지 포함) 버튼. 향후 기능 버튼 추가 여지를 위해 확장 가능한 구조로
  설계
- 제어 기능은 1차로 "이동"만 필수. 그 외(자력 ON/OFF 등)는 미정이나 추후 확장 전제로 설계

  가입. Nano B01은 `ubuntu` / `100.121.144.38`로 2026-08-16 온라인 확인됨. 대시보드 `amc`는
  Nano B01에서 조회 시 Tailnet 등록 상태이며, 해당 시점에는 전원이 꺼져 offline으로 표시됨.
  **임시 예외 (2026-08-18)**: 학교에 인터넷이 없어 나노 B01이 Tailscale에 못 붙는 상황이라, 오늘은
  나노 B01↔라파를 랜선 직결 + 고정 IP(라파 `192.168.50.20`, 나노 B01 `192.168.50.10`)로 임시
  연결. "연결 설정" 팝업의 대시보드 주소·RTSP 주소를 이 사설 IP로 바꿔 쓰면 됨 — 설계는 그대로
  Tailscale, 인터넷 생기면 원복 ([[1. 로그/2026-08-18]]).
- 이동 명령 값 범위: -100 ~ 100 (정수, 백분율). 전진/후진 축과 좌/우 회전 축 각각 이 범위로
  전송 (아케이드 스타일 2축)
- RTSP 영상 목표: 720p @ 30fps
- 현장(공모전 시연장 등) 네트워크: 폐쇄망 가능성 대비 — 휴대폰 핫스팟 우선 고려, 안 되면 이동식
  라우터(에그류, 2~3만원대) 구매 예정. Tailscale은 인터넷(코디네이션 서버) 접근만 있으면 동작
- 전원: 구매해둔 52Pi GPIO 적층형 UPS(SZH-RPI01)가 터치스크린 공식 케이스와 물리적으로 안 맞아
  포기, **USB 보조배터리 방식으로 전환** ([[02. 결정로그]]). 별도 구매 없이 기존 보유 보조배터리
  사용 — 스펙(용량/출력) 확인은 불필요, 문제 생기면 그때 대응
- 카메라: 물리적으로 한 번에 렌즈(oCam 6mm 광시야 / ArduCam 8mm 확대) 1개만 장착되므로 영상은
  RTSP 스트림 1개로 1차 구현. 단, 향후 카메라 2개 동시 운용 확장 가능성을 염두에 두고 설계
  (예: 카메라 소스 식별자를 처음부터 두거나, UI에 소스 전환 여지를 남기는 등) — 지금 당장
  멀티 스트림 구현은 하지 않음
- 쿨링: 별도 구매한 듀얼 쿨러 케이스(RBP-002)도 터치스크린 케이스와 동시 장착 불가 — 이번
  대시보드는 터치스크린 케이스만 사용(쿨러 없음). 발열은 실사용하며 모니터링 필요([[02. 결정로그]])
- 물리 형태: 로봇과 완전히 분리된 **휴대용 콘솔** — 운영자가 양손으로 들고 조작, 로봇과는
  Tailscale 무선 통신만으로 연결 ([[02. 결정로그]])
- 앱 실행 방식: **단계적 전환**
  - 개발 단계(현재): 부팅 후 대기, 필요할 때 버튼/명령으로 수동 실행
  - 시연 임박·안정화 완료 후: 전원 켜면 자동으로 앱까지 풀스크린 실행(현재 GUI OS 유지, systemd로
    자동실행 전환) — 시연장에서 별도 조작 없이 바로 쓸 수 있어야 함

## 구현 현황 (2026-08-20, 8/21 실기 전 기록)
- 코드 작업 경로: `D:\SiloRobot\rpi4-dashboard` — 볼트 밖 Git 작업 트리가 정본이며 GitHub
  `origin/main`을 추적한다.
- 연결 없이 구현한 관제·증거기록·반자율 화면 보강:
  - WebSocket status v2의 `safety`·`distance_meta`를 처리한다. 거리값 `0`은 `--`로 표시하며,
    `calibrated=false`이면 `mm` 대신 `REL`(또는 송신측 `ADC`) 단위를 표시한다.
  - `OFFLINE/NORMAL/WARNING/STOPPED` 안전 배지, 한글 사유, 자동정지 감시 활성 여부, 해제 요청과
    수신 상태에 따른 해제 거부 피드백을 표시한다.
  - `점검 기록`은 화면에 실제로 수신된 `VideoOutput` 프레임만 캡처한다. 이미지와 같은 `record_id`의
    JSONL을 날짜별 `AppDataLocation/records/YYYY-MM-DD/`에 저장하고, 이미지 실패는 `image:null`과
    오류 사유로 남긴다. 가짜·데모 이미지를 점검기록으로 만들지 않는다. 최근 3개 기록의 썸네일을
    화면에 표시한다.
  - `계획` 팝업의 사일로 폭/높이·점검폭·중첩률·안전여백·시작 모서리를 실제
    `route_plan_request`로 보낸다. Nano가 반환한 `plan`과 `mission_state`를 status WebSocket으로
    받아 실제 plan id·waypoint·진행률·일시정지/재개/취소를 표시한다. 2026-08-19 시안의 0.8초
    가짜 진행 타이머는 제거했다.
- C++/Qt Quick 대시보드 1차 구현·native build 완료 (`build/silorobot-dashboard`)
  - 위 2026-08-20 변경분은 Windows 정적 정합성 확인까지만 완료했다. RPi4가 SSH timeout이라
    native 재빌드는 남아 있다.
  - Qt 6.8.2 / CMake 3.31.6 / GStreamer 1.26.2 설치 완료
  - 한국어 UI용 `Noto Sans CJK KR` 폰트를 라파 사용자 폴더(`~/.local/share/fonts`)에 설치하고
    fontconfig 캐시 갱신 완료. 새 이미지에서는 `fonts-noto-cjk`를 시스템 전체 또는 사용자 폴더에
    설치해야 한글 버튼·설정 문구가 네모로 보이지 않는다.
  - Wayland GUI 세션에서 `--demo` 실행 확인. 800×480 기준의 **무광 산업 조종 콘솔**로 중앙 점검
    영상, **좌하단 세로 전후진축**, **우하단 가로 좌우조향축**, 우상단 비상정지·전원·자세·통신 상태를
    분리해 표시한다. 7인치 케이스를 양손으로 잡고 좌우 엄지로 조작하는 휴대용 콘솔 형태에 맞춘 배치다.

    쓰며, 정상은 저채도 녹색, 주의·데모는 황갈색, 비상정지에만 적색을 사용한다.

### 현재 화면 검증 캡처

Wayland GUI 세션에서 `--demo`로 실행한 800×480 화면이다. 실제 RTSP가 연결되면 중앙의 대기 영역을
영상이 채우고, Orin의 실제 `detection` 메시지가 올 때만 영상 위에 황갈색 결함 박스가 표시된다.

![[4. 자료/01. 대시보드 캡처/2026-08-16_04-양손-엄지-운용콘솔-최종.png]]

- 연결 정보는 하드코딩하지 않는다. 상단 `연결 설정 / CONNECTION CONFIGURATION` 메뉴에서 아래 값을
  수정하고 `저장 및 적용`하면 Qt `QSettings`(`SiloRobot/Dashboard`)에 보존되어 다음 실행에도 자동으로
  다시 적용된다.
  - 대시보드 Tailscale 주소(기본 `100.74.141.112`) — 다른 장비에 안내할 접속 주소를 만들 때 사용
  - 카메라 RTSP 주소 — 저장 직후 영상 입력에 적용
  - WebSocket 포트(기본 `8765`) — 저장 시 서버를 새 포트로 재시작
  - 화면에는 조합된 접속점 `ws://<Tailscale 주소>:<포트>`를 보여 준다. 서버는 모든 인터페이스에서
    대기하므로 주소 변경은 바인딩 변경이 아니라 다른 장비가 사용할 안내 주소 변경이다.
  - 팝업은 796×300px(800px 화면 기준 거의 풀폭)로 넓혔고, 입력 필드를 감싼 안쪽 Column에
    `width: parent.width`를 명시해 실제 입력창 폭도 720px대까지 확보했다 — 최초엔 팝업만 넓혀도
    입력창이 안 늘어나는 QML 레이아웃 버그가 있었음 ([[03. 트러블슈팅]], 커밋 `9d5718b`).
    **앱 내 커스텀 터치 키보드는 폐기했다** — 대신 라파 OS 자체 가상 키보드(squeekboard)를
    사용하며, TextField 포커스를 잡으면 자동으로 뜬다. 팝업 안 "키보드 숨기기" 버튼을 누르면
    D-Bus(`sm.puri.OSK0.SetVisible(false)`)로 확실히 내려간다 ([[02. 결정로그]],
    [[03. 트러블슈팅]] 참조).
  - 이 설정은 대시보드 자신의 재접속·수신 설정을 자동화한다. Nano B01·Orin의 WebSocket 클라이언트는
    추후 각 기기에서 이 화면에 표시된 접속점으로 한 번 설정해야 하며, 대시보드가 원격 기기의 주소를
    강제로 바꾸지는 않는다.
- 대시보드는 **WebSocket 서버**로 `0.0.0.0:8765`에서 대기. Nano B01·Orin Nano Super가
  각각 클라이언트로 접속한다.
  - Nano B01 → 대시보드 (10Hz): `{"type":"status","battery":11.8,"imu":{"roll":0.3,"pitch":-1.1,"yaw":87.4},"distance":[78,80,79],"connected":true}`
  - 대시보드 → Nano B01: `{"type":"move","throttle":-100~100,"turn":-100~100}` /
    `{"type":"stop"}` / `{"type":"stop_release"}`
  - Orin → 대시보드: `{"type":"detection","detections":[{"x":0.0~1.0,"y":0.0~1.0,"width":0.0~1.0,"height":0.0~1.0,"label":"crack","confidence":0.0~1.0}]}`
    — 좌표는 영상 폭·높이에 대해 정규화, Qt가 영상 위에 직접 박스를 그림
  - 연결 역할 식별용 `{"type":"hello","role":"nano"}` / `{"type":"hello","role":"orin"}`은
