## 1. 최종 시연 한 문장

> 바닥·벽·천장 등 절대 자세와 무관하게 정상 운용하며, 한쪽 밀착이 풀려 3점 거리 편차와 급격한
> 회전이 함께 발생하면 위험 상태로 전환해 모터 출력을 차단하고 사건을 기록한다.

시연 입력과 결과:

```text
지그를 천천히 0° → 90° → 180° 회전
→ 자세 그래픽은 회전하지만 안전 상태 NORMAL 유지

지그 한쪽을 벽면에서 급히 이격
→ d1·d2·d3 편차 증가 + IMU 각속도 증가
→ WARNING 또는 STOPPED 전환
→ 모터 정지 래치
→ 센서가 정상으로 돌아와도 정지 유지
→ 사용자가 확인 후 해제해야 재구동
```

## 4. 데이터 흐름과 책임

```text
[WT901C IMU]
   │ UART
   ▼
[Nano imu_node] ───────────────┐
                               │
[거리센서 3개] → [STM32 ADC]   │
                   │ 8B UART   │
                   ▼           ▼
             [Nano stm32_uart_bridge]
                       │
                       ▼
              [Nano safety_supervisor]
               │         │
        STOP 명령         └─ 상태·이벤트
               ▼                  │ WebSocket 10Hz
            [STM32]               ▼
               │              [RPi4 관제]
               ▼
           [모터 4개]
```

| 장치 | 책임 | 하지 않는 일 |
|---|---|---|
| STM32 | 거리 ADC, 모터 출력, 수동/자동 정지 명령의 최종 래치, 300ms 통신 페일세이프 | IMU 해석, 복합 위험 판정, UI |
| Nano B01 | IMU 파싱, 거리 텔레메트리 결합, 복합 위험 판정, 자동 STOP 반복 송신, 이벤트 로그 | 모터 PWM 직접 생성, 영상 재인코딩 |
| RPi4 | 영상·센서·안전상태 표시, 수동 정지·해제 요청, 사건 조회 | 안전판정의 유일한 주체가 되지 않음 |

**안전판정은 Nano에 둔다.** RPi4 화면이 멈춰도 Nano가 STM32에 STOP을 보낼 수 있어야 한다.
Nano 통신 자체가 끊기면 STM32의 기존 300ms 타임아웃이 마지막 방어선이다.

## 5. 기존 프로토콜 유지 원칙

목·금 1차 구현에서는 STM32↔Nano 8바이트 프로토콜을 바꾸지 않는다. 프레임 변경은 STM32·Nano
양쪽을 동시에 깨뜨려 일정 위험이 크다.

```text
상행: BB 01 d1 d2 d3 flags checksum 55
하행: AA CMD throttle turn checksum 55
```

- `d1~d3`: 최종적으로 20~150mm를 uint8로 전달
- `0`: 미보정·읽기 실패·유효하지 않음
- `flags bit0`: STM32 정지 래치
- `flags bit1`: 통신 타임아웃 이력
- 기존 예약 비트는 이번 구현에서 임의로 재정의하지 않음

### 거리 변환 단계

1. 먼저 ADC 원시값이 물체 거리에 따라 일관되게 변하는지 시리얼 디버그로 확인
2. 20·30·50·70·100·120·150mm 기준점에서 센서별 ADC를 30개 이상 수집
3. 중앙값으로 센서별 보정표 작성
4. 구간 선형보간 LUT로 mm 변환
5. 범위 밖·ADC 오류는 0 전송

보정 전 임시 영상에서는 대시보드 단위를 `ADC` 또는 `REL`로 표시해야 한다. 기존 UI가 `mm`를 붙이므로
보정 전 가짜 mm 값을 보내지 않는다. 가장 안전한 순서는 **STM32 보정 완료 후 실측 UI를 촬영**하는 것이다.

## 6. WT901C 수신

### 우선 확인할 것

- Nano에서 실제 장치명 확인: `/dev/ttyUSB*`, `/dev/ttyTHS*` 등
- 전압 레벨과 GND 공통 확인
- 실제 baud rate와 출력 프레임을 5초 이상 hex dump
- WIT 표준 11바이트 프레임이면 헤더 `0x55`, 타입 `0x51/0x52/0x53`, 마지막 checksum 확인

WIT 표준 프레임으로 확인된 경우에만 아래 후보식을 사용한다.

```text
0x51: acceleration = int16 / 32768 × 16 g
0x52: angular rate = int16 / 32768 × 2000 deg/s
0x53: angle        = int16 / 32768 × 180 deg
checksum = frame[0..9] 합의 하위 8비트
```

실물 hex가 다르면 모델 문서와 실제 프레임을 우선하며 위 식을 억지로 적용하지 않는다.

### IMU 출력 데이터

```text
roll_deg, pitch_deg, yaw_deg
gx_dps, gy_dps, gz_dps
ax_g, ay_g, az_g
valid
sample_monotonic_ms
```

- 각도는 화면 표시용
- 위험 판정에는 `gx/gy/gz`, 단시간 각도 변화량, 가속도 크기를 사용
- 최근 데이터 age가 허용범위를 넘으면 `valid=false`

## 7. WebSocket 상태 스키마 v2

기존 RPi4와 호환되도록 `imu` 객체와 `distance` 배열은 유지하고 필드를 추가한다.

```json
{
  "type": "status",
  "timestamp_ms": 0,
  "battery": null,
  "imu": {
    "roll": 0.0,
    "pitch": 0.0,
    "yaw": 0.0,
    "gx": 0.0,
    "gy": 0.0,
    "gz": 0.0,
    "ax": 0.0,
    "ay": 0.0,
    "az": 0.0,
    "valid": true,
    "age_ms": 0
  },
  "distance": [50, 51, 49],
  "distance_meta": {
    "valid": [true, true, true],
    "unit": "mm",
    "calibrated": true,
    "mean": 50.0,
    "spread": 2.0,
    "mean_rate": 0.0,
    "age_ms": 0
  },
  "safety": {
    "state": "NORMAL",
    "reasons": [],
    "latched": false,
    "armed": false
  },
  "stm32": {
    "connected": true,
    "stop_latched": false,
    "timeout_seen": false
  },
  "connected": true
}
```

### 하위 호환 규칙

- RPi4 구버전은 기존 `imu.roll/pitch/yaw`, `distance`, `connected`만 읽어도 동작해야 함
- 누락된 신규 필드는 `OFFLINE`이 아니라 `UNKNOWN`으로 취급
- 숫자가 아닌 값·NaN·Infinity는 JSON으로 보내지 말고 `null` 또는 `valid=false` 사용
- 배터리 측정 회로가 없으므로 `battery`는 `null`; 가짜 전압 금지

### 제어 메시지

기존 메시지를 우선 재사용한다.

```json
{"type":"move","throttle":20,"turn":0}
{"type":"stop"}
{"type":"stop_release"}
```

- `stop`: 수동 비상정지, Nano와 STM32 모두 래치
- 자동 위험정지 발생 시 Nano가 내부 래치를 세우고 STM32에 `SILO_CMD_STOP`을 반복 송신
- `stop_release`: 해제 요청일 뿐이다. Nano는 센서가 안정된 경우에만 내부 래치를 풀고 STM32에 해제 전송
- 위험 조건이 남아 있으면 해제를 거부하고 RPi4에 현재 reason 유지

## 8. 특징량 계산

샘플은 monotonic clock 기준으로 계산한다. 시스템 시각은 로그 표시용으로만 사용한다.

### 거리센서

```text
d_mean   = 유효한 d1,d2,d3의 평균
d_spread = max(d1,d2,d3) - min(d1,d2,d3)
d_rate   = low_pass((d_mean_now - d_mean_prev) / dt)
```

- `d_mean`: 벽면과의 전체 간격
- `d_spread`: 한쪽 들림 또는 접촉 불균형
- `d_rate`: 벽면에서 빠르게 멀어지는지
- 3개 중 1개만 무효면 WARNING 후보, 2개 이상 무효면 STOP 후보
- 곡면에서는 정상 상태에서도 편차가 생길 수 있으므로 고정 수치가 아니라 실물 정상 분포를 먼저 측정

### IMU

```text
omega = sqrt(gx² + gy² + gz²)
accel = sqrt(ax² + ay² + az²)
delta_angle = 최근 짧은 구간의 상대 자세 변화량
```

- Roll·Pitch·Yaw 절대값은 위험 판정에 사용하지 않음
- `omega`: 급격한 회전·한쪽 들림 후보
- `accel`: 충격 또는 자유낙하 징후의 보조값
- `delta_angle`: 정상적인 완만한 곡면 이동과 급격한 이탈 구분
- 자력 부착 상태에서 정지하면 바닥·벽·천장 모두 가속도 크기는 대체로 1g이므로 방향 자체를 위험으로 보지 않음

### 명령 문맥

- `abs(turn)`이 큰 동안의 완만한 yaw 회전은 정상 조향으로 취급
- 정지·직진 명령인데 큰 yaw/roll 회전이 발생하면 이상 신뢰도 증가
- IMU 이상 하나만으로 STOP하지 않고 거리 또는 통신 이상과 결합

## 9. 안전 상태머신

상태는 네 개로 고정한다.

| 상태 | 의미 | 모터 명령 |
|---|---|---|
| `OFFLINE` | 필수 센서 또는 STM32 데이터가 오래됨 | 주행 중이면 STOP, 정지 중이면 주행 금지 |
| `NORMAL` | 센서 유효·복합 이상 없음 | 사용자 명령 허용 |
| `WARNING` | 단일 이상 또는 짧은 복합 이상 | 1차는 경고 표시, 자동 감속은 실측 후 결정 |
| `STOPPED` | 심각하거나 지속된 복합 이상·수동 정지 | STOP 반복 송신, 수동 해제 전 유지 |

### 전이 원칙

```text
BOOT → OFFLINE
OFFLINE → NORMAL       필수 데이터가 연속 안정
NORMAL → WARNING       단일 이상이 debounce 시간 지속
WARNING → NORMAL       release 시간 동안 모두 정상
WARNING → STOPPED      복합 이상 또는 심각 조건 지속
ANY → STOPPED          수동 stop / Nano-RPi 통신 단절 중 주행 / STM32 이상
STOPPED → NORMAL       조건 정상 + 안정시간 충족 + 사용자 stop_release
```

### 복합 판정 예시

아래는 로직 구조이며 숫자는 실측 전 확정하지 않는다.

```text
distance_unbalanced = d_spread > calibrated_spread_limit
distance_leaving    = d_rate > calibrated_rate_limit
rotation_abnormal   = omega > calibrated_omega_limit AND not expected_turn
impact_abnormal     = abs(accel - 1g) > calibrated_accel_limit

WARNING = distance_unbalanced OR rotation_abnormal OR one_sensor_invalid

STOP = (distance_unbalanced AND rotation_abnormal)
    OR (distance_leaving AND rotation_abnormal)
    OR (distance_leaving AND impact_abnormal)
    OR two_or_more_distance_invalid
    OR telemetry_stale_while_moving
    OR manual_stop
```

### 오탐 방지

- 이동평균 또는 중앙값 필터 후 판정
- 진입 임계값과 해제 임계값을 다르게 두는 히스테리시스
- 1회 샘플이 아닌 연속 지속시간으로 판정
- 시작 직후 센서 안정화 시간 동안 자동정지 비활성
- 처음에는 `armed=false` 모니터링 전용으로 시험하고, 정상·이상 데이터 확보 후 `armed=true`
- `armed=false`여도 수동 비상정지와 기존 300ms 통신 페일세이프는 항상 활성

## 10. 초기 임계값 결정 절차

임의 숫자를 보고서에 쓰지 않는다. 아래 시험 결과로 정한다.

1. 센서 지그를 고정하고 평판과의 간격을 일정하게 유지한 정상 데이터 30초 수집
2. 지그를 천천히 0°→90°→180° 회전한 정상 방향전환 데이터 수집
3. 평판을 천천히 곡면처럼 이동한 정상 편차 데이터 수집
4. 한쪽을 급히 벌리는 이탈 모사 데이터 10회 수집
5. 지그를 짧게 흔드는 충격 데이터 10회 수집
6. 정상 최대치와 이상 최소치 사이에 1차 임계값 설정
7. 정상 10회에서 오정지 0회인지 확인
8. 이탈 모사 10회에서 경고·정지 재현 횟수 기록

실험용 설정 파일 후보:

```yaml
safety:
  armed: false
  startup_grace_ms: TBD
  stale_ms: TBD
  warn_hold_ms: TBD
  stop_hold_ms: TBD
  release_stable_ms: TBD
  distance_spread_warn_mm: TBD
  distance_spread_stop_mm: TBD
  distance_rate_stop_mm_s: TBD
  omega_warn_dps: TBD
  omega_stop_dps: TBD
  accel_deviation_g: TBD
```

값은 Nano 설정 파일에서 바꾸고 소스코드에 흩어 놓지 않는다.

## 11. 이벤트 로그

Nano가 판정 주체이므로 Nano에 JSONL 정본을 남긴다.

```json
{"time":"2026-08-21T15:42:18.120+09:00","event":"SAFETY_STOP","reasons":["DISTANCE_UNBALANCED","ROTATION_ABNORMAL"],"imu":{"roll":91.2,"pitch":2.1,"yaw":14.0,"omega":48.3,"accel":1.07},"distance":[48,51,92],"distance_mean":63.7,"distance_spread":44,"command":{"throttle":20,"turn":0},"latched":true}
```

- 상태 전이가 일어날 때만 이벤트 로그 기록; 10Hz 전체 스트림을 무한 기록하지 않음
- 최소 이벤트: `BOOT`, `SENSOR_ONLINE`, `WARNING_ENTER`, `WARNING_CLEAR`, `SAFETY_STOP`,
  `MANUAL_STOP`, `RELEASE_ACCEPTED`, `RELEASE_REJECTED`, `STM32_OFFLINE`
- 로그 파일은 날짜별 분리
- 비밀번호·Tailscale 인증정보·사용자 개인정보 기록 금지

## 12. RPi4 화면 요구사항

### 필수

- 안전 상태 배지: `OFFLINE 회색 / NORMAL 초록 / WARNING 노랑 / STOPPED 빨강`
- 안전 사유 한글 한 줄: `센서 연결 대기`, `3점 거리 편차`, `급격한 회전`, `복합 이탈 위험`
- Roll·Pitch·Yaw 표시 — **자세 표시용**임을 문서에서 명확히 함
- d1·d2·d3와 평균·편차 표시
- 정지 래치 상태와 해제 버튼
- `armed=false`이면 화면에 `모니터링 전용 — 자동정지 비활성` 상시 표시

### 영상 임팩트용

- IMU에 맞춰 회전하는 단순 로봇 도형
- 거리센서 3개의 길이를 막대 또는 광선으로 표시
- 천천히 회전할 때는 로봇 도형만 회전하고 안전 배지는 초록 유지
- 한쪽 거리가 벌어질 때 해당 광선·막대가 빨간색으로 바뀜
- STOPPED 전환 시 화면 가장자리 빨간 테두리와 정지 원인 표시

### 데모 모드 구분

- 기존 `--demo` 가짜 센서값은 UI 개발에만 사용
- 실제 촬영에서 demo mode를 사용하지 않음
- 불가피하게 UI 설명 화면을 쓰면 화면 전체에 `UI 시뮬레이션` 워터마크 표시

## 18. 프로파일 장착 상태의 외란 모사 시험

현재 모터·제어기가 프로파일에 장착된 상태를 그대로 사용한다. 무작위로 세게 흔드는 것이 아니라
프로파일에 통제된 외란을 주고 센서 변화·경고·모터 정지를 반복 검증한다.

### 권장 지그

- 프로파일 양 끝을 낮은 받침 또는 고무패드 위에 올려 모터 바퀴가 바닥에 닿지 않게 함
- 한쪽 받침을 힌지 또는 회전축처럼 사용하고 반대쪽에 절연 손잡이 설치
- IMU는 프로파일에 단단히 고정해 프로파일의 실제 회전을 그대로 측정
- 거리센서 3개는 번호와 위치를 표시하고 고정된 평판을 바라보게 배치
- 전원선·USB·센서선은 케이블타이로 strain relief 처리
- 모터·바퀴·커플러의 회전면과 손잡이 위치를 분리
- 프로파일이 테이블 밖으로 떨어지지 않도록 보조 안전줄 또는 클램프 사용

### 시험 시나리오

| ID | 외란 | 방법 | 기대 센서 반응 | 기대 시스템 반응 |
|---|---|---|---|---|
| D1 | 정상 자세 변경 | 프로파일을 천천히 기울이거나 센서 지그를 완만히 회전 | 절대 자세 변화, 낮은 각속도, 거리 안정 | `NORMAL` 유지 |
| D2 | 급격한 흔들림 | 절연 손잡이로 짧고 통제된 좌우 회전 외란 | IMU 각속도·가속도 급변, 거리 변화 작음 | 단일 징후면 `WARNING`, 즉시 STOP 여부는 실측 후 결정 |
| D3 | 한쪽 들림 | 프로파일 한쪽을 평판에서 빠르게 몇 cm 이격 | 한쪽 거리 증가·spread 증가 + IMU 회전 | 복합 조건 지속 시 `STOPPED` |
| D4 | 전체 이격 | 프로파일을 평판과 평행하게 빠르게 멀리 이동 | d1·d2·d3 동시 증가·mean_rate 증가 | 심각 조건이면 `STOPPED` |
| D5 | 진동 반복 | 작은 외란을 짧게 반복 | IMU 진동 증가, 거리 편차 간헐 발생 | debounce 전이면 유지, 지속 시 경고 |
| D6 | 통신 단절 | 주행 중 Nano↔STM32 케이블 또는 프로세스 중단 | 센서 stale/통신 끊김 | 기존 300ms 페일세이프 정지 |

### 촬영 순서

1. 모터 저속 회전과 `NORMAL` 초록 상태를 한 프레임에 촬영
2. D1을 수행해 자세값은 바뀌지만 정상 상태가 유지됨을 증명
3. D2를 수행해 IMU 변화와 노란 경고를 증명
4. D3을 수행해 거리 막대 한쪽 증가·빨간 전환·모터 정지를 증명
5. 프로파일을 원위치로 돌려도 정지 래치가 유지됨을 증명
6. 사용자가 해제한 뒤 별도 재개 명령으로 모터가 다시 회전하는 장면 촬영

### 안전 주의

- 회전 중인 바퀴를 손으로 강제 정지하지 않음 — 끼임·순간전류·드라이버 손상 위험
- 프로파일을 들고 흔들면서 전원단자·노출 배선을 잡지 않음
- 강한 충격보다 작은 외란으로 시작해 센서 그래프를 보며 단계적으로 증가
- Li-Po 배터리를 장착한 채 낙하 모사를 하지 않음. 벤치 전원 사용을 우선
- 자동정지 첫 시험은 모터 전원을 끄거나 바퀴를 완전히 띄운 상태에서 STOP 명령부터 확인
- 각 시험의 외란 강도는 실측 전 임의 수치로 보고서에 기재하지 않음

보고서 표현은 `프로파일 기반 외란 모사 벤치 시험` 또는 `센서 복합 안전정지 HIL 검증`을 사용한다.
`실제 벽면 이탈 시험`이나 `낙하 방지 검증 완료`로 표현하지 않는다.
