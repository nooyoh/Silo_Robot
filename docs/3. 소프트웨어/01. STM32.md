# STM32

> 2026-08-19 목·금 센서 기능개발은 [[3. 소프트웨어/04. 센서-안전감시 구현명세]]를 정본으로 사용.
> 이 파일의 기존 8바이트 텔레메트리는 유지하고 ADC 실측·거리 LUT를 완성한다.
> 이후 반자율 주행은 [[3. 소프트웨어/05. 반자율 전면점검 구현명세]]에 따라 좌·우 엔코더 입력과
> 별도 13바이트 누적 카운트 프레임을 추가한다.

로봇 본체 내 실시간 모터 제어 담당. 젯슨나노 B01과 내부 통신으로 연결되며, 베어메탈로 동작해
실시간성을 확보한다. 2026년 한이음ICT 재료 2차에서 NUCLEO-F401RE로 구매됨 ([[06. 예산]]).

## 구성
- 모터 드라이버 2개(DFR0601, -12A, 듀얼채널) — 드라이버 1개당 모터 2개 제어, 총 모터 4개
  (좌/우 궤도 각 2개) ([[05. 부품표]], 부품표 수량 1개로 기재된 건 오류로 확인됨 — 실제 2개 구매)
- PWM은 드라이버 2개 × 2채널 = **총 4채널** (모터 4개 각각)
- 엔코더: 모터 4개 중 좌/우 각각 앞쪽 모터에만 장착(뒤쪽은 엔코더 없음)
- 거리센서 3점(SHARP GP2Y0A51SK0F, 아날로그 출력) — **STM32 내장 ADC 3채널로 읽음.**
  Nano B01에 ADC가 없어 직결 불가하기 때문 ([[02. 결정로그]])
- 베어메탈 펌웨어, STM32CubeIDE + HAL 라이브러리 사용 ([[02. 결정로그]])

       (RTOS 미사용) — 보고서에 예산표 문구를 그대로 옮기지 말 것 -->

- 보드: **NUCLEO-F401RE로 확정** (2026-08-21 플래시 시 `STM32_Programmer_CLI`가 Device ID
  `0x433`/`STM32F401xD/E`·Board `NUCLEO-F401RE`로 자동 인식, 구매 기록·부품표와 일치 —
  [[91. 질문지]] H-27 종결). 2026-08-18 실기에 쓰인 실물은 별도의 F411RE 보드였던 것으로 정리.
  펌웨어는 `DEVICE=f401`(기본)/`DEVICE=f411`로 양쪽 다 빌드 가능하게 남겨둠(두 보드 모두
  NUCLEO-64 핀아웃 동일, TIM3/4·USART2·ADC1·GPIO 레지스터도 동일해 핀맵·배선 공용)
- 모터: 웜기어 엔코더 모터 WGM40-3150-1280E, 12V, 감속비 1/290 ([[05. 부품표]] 2025년 해운물류
  구매분, 2026년에도 동일 사용)
- 모터 드라이버: DFR0601, -12A, 듀얼채널

## 통신 (Nano B01 ↔ STM32)
- 물리: USB — NUCLEO-F401RE 내장 ST-LINK의 VCP(가상 시리얼포트) 이용, USB 케이블 1개로 전원
  공급 + UART 통신 겸용 ([[02. 결정로그]])
- **현재 조립도 USB 유지.** 점퍼 전원+GPIO UART 대안은 납땜 변경과 IMU 포트 이동이 필요해
  비권장으로 남겼다. 정확한 대안 핀은 [[2. 하드웨어/05. 배선도]]만 따른다.
- 명령 내용: 대시보드와 동일한 축 값(throttle/turn, -100~100)을 Nano가 그대로 전달 — 좌/우
  모터 듀티비 믹싱(아케이드 스타일)은 STM32 쪽에서 수행
- 양방향: 하행 6바이트 제어 / 상행 `BB` 거리 8B·`BC` 엔코더 13B·`BD` 원시 ADC 11B(20Hz)·
  `BE` 배터리 9B(2Hz).
  프레임 정의는 [[3. 소프트웨어/02. 젯슨]] 텔레그램 절 참조

### 거리센서 (SHARP GP2Y0A51SK0F ×3)

- Vcc는 5V, 출력(Vo)은 10kΩ+0.1uF RC(약 159Hz LPF) 거쳐 MCU로 — 최대 출력이 3.3V 미만인지
  **연결 전 멀티미터로 반드시 확인**. 10kΩ을 넣었으면 ADC 샘플링 시간을 480사이클로 늘려야 함.
  상세 핀과 배선은 [[2. 하드웨어/05. 배선도]] 참조.

### 배터리 전압 감시 (코드 완료, 회로 미배선)

GitHub `main` 최신 커밋은 `4de305d`. 새 핀맵 ARM build와 F401RE 실물 flash/verify/reset 완료,
12선 재배선·도통·모터 시험은 아직이다.

- 회로·임계값 상세는 [[2. 하드웨어/04. 전원]] 참조(아직 배선 안 됨).

### 모터 드라이버 2개

DFR0601은 모터 채널마다 `PWM`, `INA`, `INB` 세 입력이 필요하다. 정확한 좌·우 채널과 핀은
[[2. 하드웨어/05. 배선도]] §3만 따른다.

### 엔코더 (WGM40-3150-1280E, AB 2상 증분형 16PPR) — 하드웨어 타이머 모드

- 정확한 엔코더 타이머·헤더 핀·커넥터 순서는 [[2. 하드웨어/05. 배선도]] §4만 따른다.
- **부호 규약 (2026-08-21 밤 최종 확정)**: **좌·우 모두 "카운트 감소 = 전진"** →
  `meters_per_count_left`·`right` **둘 다 음수**. 세션 도중 "우측만 음수" 설정을 거쳤는데
  그건 오류였다 — 좌우 스케일 부호가 반대면 제자리 회전이 "직진"으로 적분되어 회전각이
  0으로 붕괴한다(실측 대입 검산 완료). **좌우는 반드시 함께 뒤집을 것.**
- 이 부호는 `path_follower`의 조향 부호와 **한 쌍**이다. 하나만 바꾸면 조용히 발산한다.
  상세 경위는 [[03. 트러블슈팅]] 2026-08-21 밤 항목.
- 웜기어 자체잠김이라 손으로 돌려 확인 불가 — 조향 명령을 걸고 `watch_wheels`로 실측했다.
  배선을 바꿨으면 `ros2 run silorobot_nano verify_signs`로 두 부호를 한 번에 판정할 것.
- 근거 이미지: [[4. 자료/02. 모터 자료/2026-08-16_WGM40-3150-1280E_사양-엔코더-핀맵.png]]

### DFR0601 제어 논리

| INA | INB | PWM | 모터 상태 |
|---|---|---|---|
| LOW | LOW | 무관 | 정지 |
| LOW | HIGH | 듀티비 | 정방향 |
| HIGH | LOW | 듀티비 | 역방향 |
| HIGH | HIGH | 무관 | 출력 플로팅(Hi-Z) |

- NUCLEO GND와 DFR0601 제어 GND는 반드시 공통 접지한다.
- DFR0601 제어부 VCC는 **NUCLEO 3V3**를 사용한다(2026-08-24 네 채널 실물 구동 확인).
  모터 전원 `P+`/`P-`와 혼동하지 않는다.
- 방향을 즉시 반전하지 않는다. 펌웨어는 약 100ms 감속 램프로 PWM 0을 거친 뒤 반대 방향으로 올린다.
- 비상정지와 300ms 통신 타임아웃은 감속 없이 `PWM=0`, `INA=LOW`, `INB=LOW`로 즉시 정지한다.

## 제어 로직
- 대시보드 이동값(-100~100, 전후진축/좌우회전축)을 좌/우 모터 PWM 듀티비 0~100%로 선형 매핑
  (1차 잠정, 실측 후 데드존·최대치 보정 예정, [[02. 결정로그]])
- 정지(비상정지): throttle=0/turn=0과 구별되는 별도 정지 명령. 수신 즉시 PWM 0 강제, 명시적
  해제 전까지 래치. 통신 끊김(타임아웃) 시에도 STM32 자체적으로 PWM 0 페일세이프 ([[02. 결정로그]])

## 빌드·플래시 (2026-08-18 확립)
- 레포에 `.cproject`가 없어 CubeIDE로 임포트해도 빌드·디버그 설정을 손으로 만들어야 한다.
  **CubeIDE에 동봉된 툴체인을 PATH에 넣고 `make`, 굽는 건 `STM32_Programmer_CLI`가 빠르다.**
- 빌드: `make DEVICE=f411 BUILD_DIR=<로컬 임시폴더>` (F401RE면 `DEVICE` 생략)

    반드시 로컬 임시 폴더를 쓸 것
- 플래시: `STM32_Programmer_CLI.exe -c port=SWD -w <build>/silorobot-f401re.bin 0x08000000 -v -rst`

## 실측값 (2026-08-18, 무부하 벤치)
- **모터 4개 전부 회전 확인.** `throttle=20`에서 이미 회전 → **데드존은 20% 미만**,
  정확한 값은 더 낮춰가며 재측정 필요
- **방향 전환 시 순간 전류 1.7A** (파워서플라이 관측)
  - ⚠ **무부하 값이다.** 등반 부하에서는 정격(개당 1.6A)에 근접하거나 넘고 스톨은 개당 6.5A —
    **이 숫자로 배터리·드라이버·배선을 사이징하지 말 것**
- 좌우 회전 방향: 펌웨어는 좌우에 **동일 극성**을 보낸다(`silo_motor_driver.c`에 좌우 반전 없음,
  믹싱은 `left=throttle+turn` / `right=throttle-turn`). 실측에서 `throttle`만 주면 좌우가 반대,
  `turn`만 주면 좌우가 같은 방향으로 돌아 **한쪽 배선이 뒤집힌 상태로 일관 확인됨** — 소프트웨어
  정상. **한쪽 모터 `M_A`/`M_B`를 바꿔 끼워 해결하기로 결정**(펌웨어에 반전 플래그 추가 안 함).
  판정 기준은 장착 후 `throttle=+`일 때 양쪽 궤도가 로봇을 같은 방향으로 미는지.
