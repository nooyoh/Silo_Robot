# 젯슨

> 2026-08-19 목·금 센서 기능개발은 [[3. 소프트웨어/04. 센서-안전감시 구현명세]]를 정본으로 사용.
> Nano B01이 IMU 파싱·거리 결합·복합 위험 판정·자동 STOP의 주체다.
> 안전감시 이후에는 [[3. 소프트웨어/05. 반자율 전면점검 구현명세]]에 따라 오도메트리·경로추종·
> 안전정지 후 경로 재개도 Nano B01이 담당한다.

컴퓨팅 보드 2종을 역할 분리해서 쓴다 — 로봇 탑재용(Jetson Nano B01)과 서버용(Jetson Orin
Nano Super). 원래 Nano B01 하나로 다 처리하려 했으나 실시간 영상처리 성능이 부족해 영상 처리를
Orin Nano Super로 넘긴 구조. ([[02. 결정로그]] 참조)

## 구성
- **Jetson Nano B01** (로봇 탑재, 2025년부터 사용 — [[05. 부품표]] "2025년 해운물류 구매분")
  - STM32와 통신해 모터 제어 외 로봇 측 두뇌 역할 전반 수행
  - 영상 데이터는 자체 처리하지 않고 RTSP로 Orin Nano Super에 송신
  - 개발 언어/프레임워크: **ROS2 Eloquent**, Python(rclpy) 중심, 기능별 노드 분리 ([[02. 결정로그]]
    — Ubuntu 18.04 arm64에서 공식 바이너리로 설치 가능한 ROS2 배포판)
  - ROS2 Eloquent ROS-Base 설치·`ros2` CLI 실행 확인 완료(2026-08-16). GUI 패키지는 Nano에
    불필요하므로 설치하지 않음
  - 카메라: CSI 리본 커넥터, GStreamer `nvarguscamerasrc`로 RTSP 송신(720p30, 대시보드 스펙과 동일)
  - IMU(WT901C/UART): STM32 경유 없이 Nano B01 GPIO UART(`/dev/ttyTHS1`)에 3.3V TTL로 직결,
    독립 ROS2 노드가 읽어 상태로 퍼블리시. **배선**: WT901C TX→Nano 10번 RX / RX←8번 TX
    (교차), VCC→1/17번 3.3V, GND 공통. `nvgetty`를 비활성화해야 한다.
    `imu_node`가 이미 배포·자동재접속 중이라 배선만 맞으면 꽂는 즉시 인식됨(플래시 불필요) —
    확인은 `ros2 topic echo /silorobot/imu_health`(connected/valid, types_seen에 0x51/52/53)
  - 거리센서 3점(SHARP GP2Y0A51SK0F): **아날로그 출력이고 Nano B01에 ADC가 없어 STM32 ADC 경유**
    — STM32가 상행 UART 텔레메트리로 올리고, UART 브릿지 노드가 파싱해 퍼블리시 ([[02. 결정로그]])
  - WebSocket: 대시보드(RPi4)가 서버, Nano B01은 클라이언트로 접속 ([[02. 결정로그]])
  - 계정: **`jetson@ubuntu`** (SSH 시 `ssh jetson@<IP>`). `/dev/ttyACM0` 접근에 **dialout 그룹
    필요** — `sudo usermod -aG dialout jetson` 후 재로그인 ([[03. 트러블슈팅]])
  - Tailscale: 설치·동일 Tailnet 로그인 완료(2026-08-16). hostname `ubuntu`, Tailscale IPv4
    `100.121.144.38` — 대시보드와의 WebSocket, Orin·대시보드 RTSP 접속에 사용
- **Jetson Orin Nano Super** (서버 역할, 2026년 해운물류 예산으로 구매 — [[06. 예산]])
  - Nano B01로부터 RTSP로 영상 수신, TensorRT로 결함탐지 추론
  - 결과(결함 좌표)는 Tailscale을 통해 대시보드(RPi4)에 직접 WebSocket으로 전송 (Nano B01 경유
    안 함), 동일 데이터를 로컬 로그로도 저장
  - 그 외 서버 역할 전반(영상처리 이외 서버 기능) 담당

## Nano B01 ↔ STM32 텔레그램 포맷 (1차, 실측 전 잠정)
- 하행 (Nano → STM32, 제어): `[0xAA][CMD][throttle_i8][turn_i8][checksum][0x55]` 6바이트 고정
  - CMD: `0x01`=이동, `0x02`=정지(래치), `0x03`=정지 해제
  - checksum: CMD~turn XOR
  - 전송 주기 50ms(20Hz), STM32 자체 타임아웃 300ms(기존 페일세이프와 일치)
- 상행 (STM32 → Nano, 텔레메트리): `[0xBB][TLM][d1][d2][d3][flags][checksum][0x55]` 8바이트 고정
  - `d1~d3`: 거리센서 3점, uint8, 단위 mm (GP2Y0A51SK0F 측정범위 20~150mm)
  - `flags`: bit0=정지 래치 상태, bit1=통신 타임아웃 이력, 나머지 예약
  - checksum: TLM~flags XOR (하행과 동일 규칙), 전송 주기 50ms(20Hz)
  - 같은 ST-LINK VCP UART를 양방향으로 사용
- [[3. 소프트웨어/01. STM32]] 쪽 "미확정" 항목(UART 텔레그램 포맷)에 대응하는 확정 사항

## Nano B01 ↔ 대시보드 WebSocket JSON 스키마 (1차)
- 상태 (Nano→대시보드, 10Hz): `{"type":"status","battery":,"imu":{"roll":,"pitch":,"yaw":},"distance":[d1,d2,d3],"connected":}`
- 제어 (대시보드→Nano): `{"type":"move","throttle":-100~100,"turn":-100~100}` / `{"type":"stop"}` / `{"type":"stop_release"}`

## 2026-08-21 전원 인가 자동 기동 확정

## 2026-08-24 최신 코드와 배포 상태

- GitHub `main`과 Nano 실기기 모두 `ddf1b59`. Nano의 HTTPS Git 인증이 없어 Windows의 검증된
  Git bundle을 Tailscale SSH로 전달해 작업 트리를 fast-forward했다.
- 엔코더 부호, 경로 추종 조향 부호, 계획 좌표와 오도메트리 좌표 기준점 오류를 수정했다.
- 장치 외 검증 스위트 `tools/verify/run.py`의 63개 항목(자율 32 + 통신·안전 31)과 패키지 계약
  4개가 통과했다.
- 거리센서 미연결 상태가 자동 시작을 막지 않도록 autostart의 `require_distance:=false`를 반영했다.
- Nano에서 `silorobot_nano` build 성공 후 systemd를 최신 코드로 재기동했다. 8개 노드가 중복 없이
  실행되고 IMU `/dev/ttyTHS1` 연결, RTSP `:8554` 리슨, RPi WebSocket 연결을 확인했다.
- 현재 `/dev/ttyACM0`이 없어 STM32 브릿지만 안전 재접속 대기 중이다. STM32 USB를 Nano에 연결하면
  자동 인식되는지 preflight와 상태 토픽으로 확인한다.
- 엔코더 좌·우 스케일은 모두 ‘카운트 감소=전진’을 기준으로 음수를 사용하되, `straight 1.0 20`
  실측으로 `count/m`을 확정해야 한다.
- pose·safety·wheel count 수신 freshness와 4초 무진행 watchdog을 추가했다. 입력이 끊겼는데 마지막
  비영점 명령만 계속 살아 있는 상태는 `PAUSED_SAFETY` 또는 `RECOVERY_REQUIRED`로 정지한다.
- 이론 시작값은 좌우 `-0.000014476541 m/count`, track width `0.294m`, waypoint radius `0.15m`,
  max throttle/turn `50/45`다. 작은 HIL 시뮬레이션은 완주하지만 실측 정확도를 뜻하지 않는다.
- `0xBE` 배터리 프레임을 대표 전압·팩별 mV·flags로 발행하고 dashboard/safety status에 합친다.
  감시 bit가 켜진 상태의 invalid/stale 배터리는 정지 해제를 거부한다.
- 일반 systemd 부팅은 `allow_unarmed_autonomy=false`를 유지한다. 거리센서·IMU 안전 판단을
  제외한 촬영/HIL은 서비스를 중지하고 `bash scripts/silorobot.sh demo-drive`를 명시 실행해야
  한다(`bench-autonomy`는 호환 별칭).
