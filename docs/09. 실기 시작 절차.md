# 09. 실기 시작 절차 — 꽂고 바로 되게

전원 넣고 자율주행까지 가는 **최단 경로**. 배선 자체는 [[2. 하드웨어/05. 배선도]]가 정본이고,
이 문서는 "배선이 되어 있다는 전제에서 무엇을 어떤 순서로 하는가"만 다룬다.

**현재 하드웨어 상태 전제**: STM32·모터 4개·엔코더 2개·IMU·카메라 연결됨.
**거리센서 3점과 배터리 감시는 아직 미배선.**

---

## 0. 딱 한 번만 (코드 최신화)

2026-08-24 STM32 좌우 묶음 핀맵과 전면 관제 수정까지 반영됐다. **두 기기 모두 이 단계를 거쳐야
한다.** 안 하면 어제와 똑같이 제자리에서만 돈다.

> 2026-08-24 Nano `ddf1b59`·RPi `7a5c99c` 배포와 서비스 기동까지 완료했다. 이후 새 커밋이
> 생겼을 때만 아래 업데이트 절차를 다시 수행한다.

> [!danger] STM32는 펌웨어와 배선을 반드시 함께 바꾼다
> `stm32-controller@4de305d`가 현재 기준이다. 핀 번호는 이 문서에 복제하지 않는다.
> **모터 전원 OFF**에서 [[2. 하드웨어/05. 배선도]]의 단일 정본대로 12선을 재배선한 뒤 F401RE용
> `silorobot-f401re.bin`을 플래시한다. 예전 배선에 새 펌웨어, 새 배선에 예전 펌웨어를 쓰지 않는다.

### 나노 B01

```bash
cd ~/jetson-nano-b01
git pull
source /opt/ros/eloquent/setup.bash
colcon build --symlink-install --packages-select silorobot_nano
sudo systemctl restart silorobot-nano.service
```

### 라파 (대시보드)

```bash
cd ~/rpi4-dashboard
git pull
cmake --build build
bash scripts/install-autostart.sh   # 최초 1회만
```

빌드 후 앱을 **종료했다가 다시 실행**해야 새 화면이 뜬다(실시간 위치 마커·재연결 버튼).

## 1. 전원 순서

1. **나노 B01 전원** — systemd가 8개 노드를 자동 기동한다. 별도 명령 불필요
2. **라파 전원** → §0 설치를 마쳤으면 자동 기동. 아직 설치 전이면 바탕화면 아이콘 탭
3. **모터 전원은 마지막**. 궤도를 공중에 띄운 상태에서 넣는다

정상이면 나노 로그에 `RTSP ready`와 `Connected to dashboard WebSocket`이 뜬다:

```bash
journalctl -u silorobot-nano.service -f
```

|---|---|

## 3. 자율주행까지

일반 부팅은 `armed=false`라 자율 시작을 의도적으로 거부한다. 궤도를 공중에 띄운 HIL에서만
아래 명령으로 **먼저** 실행 모드를 바꾼 뒤 화면 절차를 시작한다. 서비스가 켜져 있으면 중복
publisher 방지를 위해 스크립트가 거부하며, 터미널에서 `BENCH`를 직접 입력해야 한다.

```bash
sudo systemctl stop silorobot-nano.service
bash scripts/silorobot.sh demo-drive
```

터미널에 `DEMO`를 입력한다. 기존 `bench-autonomy`도 호환 별칭으로 남아 있으며 그 명령은
`BENCH`를 요구한다. 시연 모드는 거리·IMU 자동판단과 armed 자율 게이트만 우회하고, 대시보드
비상정지·STM32 정지 래치·300ms 통신 타임아웃은 유지한다.

1. **`해제 요청`** 탭 → 상태가 `STOPPED → RELEASING → NORMAL`로 넘어간다 (약 1~2초)
   - `NORMAL`이 안 되면 아래 §5 참조. **`NORMAL`이 아니면 시작 버튼이 조용히 무시된다**
2. **`계획`** → 값 입력 → **`추천 경로 생성`**
3. **로봇을 시작 모서리에 첫 구간 방향으로 놓는다** — 시작을 누른 그 자리·그 방향이 계획의
   출발점으로 고정된다(anchor). 그래서 정렬 없이 바로 출발한다
4. **`시작`** 탭

시험을 끝내고 `demo-drive`를 `Ctrl+C`로 종료한 뒤 일반 안전 부팅으로 되돌린다:

```bash
sudo systemctl start silorobot-nano.service
```

### 빠른 확인용 계획값

| 항목 | 값 |
|---|---|
| 사일로 폭 (m) | 0.5 |
| 사일로 높이 (m) | 0.5 |
| 점검폭 (m) | 0.3 |
| 중첩률 (%) | 20 |
| 안전여백 (m) | 0.05 |

→ 현재 간격 보장 알고리즘 기준 웨이포인트 **6개**짜리 짧은 경로. 수십 초 안에 진행률 100%까지 확인된다.

## 4. 되고 있다는 증거

- **화면 마커가 실시간으로 움직인다.** 예전엔 웨이포인트에 "도착"해야만 움직여서, 실제로는
  가고 있는데도 멈춰 보였다. 이제 실제 위치를 따라간다
- 나노 launch 로그에 1초마다 찍히는 줄에서 **`dist=` 값이 줄어든다**:

```text
wp0 target=(0.25,0.45) pose=(0.10,0.18,62.0deg) dist=0.31m heading_err=3.2deg
```

`dist`가 안 줄면 §5로.

## 5. 안 될 때

| 증상 | 원인·조치 |
|---|---|
| 영상 안 뜸 | 헤더 `재연결` 탭. 그래도 안 되면 나노 `journalctl`에서 `RTSP ready` 확인 |
| 해제가 거부됨 | 사유를 볼 것. `STM32 연결 끊김`이면 USB 케이블·`/dev/ttyACM0` 확인 |
| 상태가 `OFFLINE`에서 안 나옴 | STM32 미연결이거나 `require_distance`가 true로 떠 있음 (§0 최신화 안 한 경우) |
| 시작을 눌러도 반응 없음 | 안전상태가 `NORMAL`인지 먼저 확인 — 아니면 무시된다 |
| 계속 제자리에서만 돌고 진행률 0% | **부호 문제.** `ros2 run silorobot_nano verify_signs` 실행 후 전진 한 번·우회전 한 번 밀면 어느 부호를 뒤집을지 판정해준다 |
| 한쪽 궤도만 앞뒤로 떨림 | 헤딩 노이즈. `heading_deadband_deg`를 올린다 (현재 5도) |
| 모터가 너무 느림/빠름 | `bootstrap.yaml`의 `max_throttle`·`max_turn` (현재 50/45, **벤치용 임시값**) |

### 부호 판정 도구

```bash
ros2 run silorobot_nano verify_signs
```

켜놓고 대시보드로 **전진 한 번, 우회전 한 번**만 밀면 두 부호 각각 "정상 / 뒤집힘(어디를
고칠지)"을 판정해준다. 배선을 바꿨으면 반드시 이걸 먼저 돌린다.

## 6-1. 정확도 한계 — 시뮬레이션 실측 (2026-08-22)

현실 조건(궤도 슬립·좌우 출력 편차·엔코더 노이즈·손으로 놓는 오차)을 넣고 실제 코드를 돌린
결과다. **알고 있어야 보고서에 과장을 안 쓴다.**

> [!warning] 진행률 100%는 "제대로 훑었다"는 뜻이 아니다
> 추종기는 **자기 추정 위치**만 보고 도착을 판정한다. 오도메트리가 틀어져도 그걸 모르므로
> **항상 완주로 뜬다.** 화면의 진행률·완주는 "계획대로 갔다"의 증거가 아니다.

경로 길이별 실제 이탈량 (엔코더 방향 기준, 슬립 4% 가정):

| 계획 | 경로 길이 | 최종 위치 오차 | 계획 영역 이탈 |
|---|---|---|---|
| 0.5 × 0.5 m | 1.2 m | 약 2 cm | 없음 |
| 2 × 1 m | 8 m | 약 41 cm | 약 8초간 이탈 |

**시연은 작은 영역으로 할수록 안전하다.** 경로가 길수록 오차가 비례해 커진다.

### [필수] 자율주행 전에 엔코더 스케일을 실측할 것

지금 `meters_per_count`는 **사양서 기반 추정치**(16PPR × 290 × 4 = 18,560 count/rev)다.
이게 틀리면 **완주는 뜨는데 실제로는 전혀 다른 크기로 돈다.** 1×1m 계획 기준 실측:

| 엔코더 스케일 | 완주 | 실제로 훑은 범위 (목표 0.80 × 0.80 m) |
|---|---|---|
| 정확 | O | 0.88 × 0.76 m — 정상 |
| 2배 과대 | O | 0.76 × 0.88 m — 짧게 끝남(안전한 쪽) |
| **절반 과소** | O | **0.96 × 3.80 m — 0.8m 갈 자리를 3.8m 감** |

`track_width`도 30%만 틀리면 훑는 범위가 0.37m ~ 1.51m로 요동친다.

> [!danger] 과소추정이 위험하다
> 로봇이 "아직 덜 갔다"고 믿어서 계속 간다. **벽면·고소 작업에서는 판 밖으로 나갈 수 있다.**
> 그리고 **이건 소프트웨어로 못 잡는다** — 엔코더만으로는 스케일 오차가 원리적으로 관측
> 불가능하다(자기 자로 자기를 재는 셈). 실측 외에 방법이 없다.

**절차** (평평한 바닥, 1m 자 준비):

```bash
cd ~/jetson-nano-b01
bash scripts/silorobot.sh straight 1.0 20
```

정확히 1m 직진시키고, 출력된 `meters_per_count` 추천값을
`src/silorobot_nano/config/bootstrap.yaml`에 넣은 뒤 재빌드한다.
제자리 360° 회전으로 `track_width_m`도 같은 방식으로 보정할 수 있다
(`bash scripts/silorobot.sh turn 6.283185307 <좌scale> <우scale> 20`).

**실측 전까지는**: 평평한 바닥에서 **작은 계획(0.5×0.5m)으로만**, 주변에 여유 공간을 두고
돌릴 것. 벽면 자율주행은 실측 후에.

### 정확도를 올리려면 — 자이로 방향 (선택)

`bootstrap.yaml`의 `encoder_alpha: 1.0` → `0.0`으로 바꾸면 회전을 엔코더 대신 IMU 자이로로
추정한다. 자이로는 궤도 슬립의 영향을 안 받아서 실측상 훨씬 정확하다:

| 슬립 | 엔코더 (현재 기본) | 자이로 |
|---|---|---|
| 0% | 0.146 m | 0.118 m |
| 4% | 0.413 m, 8초 이탈 | **0.123 m, 이탈 없음** |
| 15% | 1.207 m, 25초 이탈 | **0.168 m, 이탈 없음** |

**바꾸기 전에 반드시**: 로봇을 제자리에서 몇 초 회전시키고 launch 로그를 본다.
`Heading sources disagree` 경고가 **안 뜨면** IMU 축이 정상이므로 바꿔도 된다.
**뜨면 IMU 축이 로봇 요축과 안 맞는 것**이니 바꾸지 말 것(조용히 완전히 틀린 방향으로 간다).

기동 후 약 10초는 자이로 바이어스를 재느라 엔코더로 방향을 잡는다. 그동안 로봇을 가만히
두는 게 좋다(어차피 정지 래치 상태라 자연스럽다).

## 7. 아직 안 되는 것 (정상)

- **거리센서 3점** — 미배선. 그래서 `require_distance:=false`로 부팅한다
  ([[2. 하드웨어/05. 배선도]] §5). **배선하면 `scripts/silorobot-autostart.sh`에서 그 인자를
  지워 true로 되돌릴 것**
- **배터리 잔량** — `0xBE` 파싱·저전압 래치 코드는 완료. 감시 회로 미배선이며 펌웨어 기본
  `BATTERY_MONITOR=0`이라 화면에 `--`
- **결함탐지(오린)** — 모델·연동 미완
- **`armed=false`** — 자동 안전정지는 꺼져 있다(임계값이 아직 추정치라 의도적).
  비상정지·정지 래치·300ms 통신 페일세이프는 살아 있다
- **라파 앱 자동실행** — 서비스·설치 스크립트는 준비됨. 라파에서 최신 build 후 설치 1회 필요
- 데드존·최대속도·엔코더 count/rev·거리 LUT — **전부 실측 필요**. 지금 값은 추정치라
  주행 거리·각도의 절대 정확도는 보장되지 않는다(수렴은 되지만 축척이 어긋날 수 있음)
