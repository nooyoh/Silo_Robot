## Claude Code 세션 — 라파 대시보드 원격 버그 수정 (아래 §9 "배포 전 확인"과 관련)

Claude Code가 SSH(코덱스 전용 키)로 라파에 직접 접속해 대시보드 실물 버그를 다수 발견·수정. 나노
B01은 "다른 세션이 최신화 중"이라는 사용자 지시로 건드리지 않음. 코드 정본은
`D:\SiloRobot\rpi4-dashboard` (원격 `SiloRobot/rpi4-dashboard`), 라파 작업 경로는
`~/rpi4-dashboard`.

**커밋 순서** (`main`): `9d5718b`(팝업 폭 버그, 이전 세션) → `99dee49`(OS 키보드 억제, 이후 방향
전환으로 폐기) → `0b97300`(커스텀 키보드 제거, OS 키보드 사용으로 전환 — 사용자가 명시적으로
방향 전환 지시) → `e8b468d`(경로계획 Repeater `index` 누락 수정) → `a24442f`(풀스크린 적용) →
`ac333d7`(진짜 fullscreen 대신 frameless 창으로 전환 — exclusive fullscreen이 OS 키보드
오버레이를 가리는 것으로 의심) → `981b1c6`(앱 내 "키보드 숨기기" 버튼 추가) →
`54c87fe`→`662d308`(팝업 뒤 배경 위젯으로 터치가 새는 문제 대응, MouseArea 차단막 추가) →
`4a91ac6`(squeekboard D-Bus `SetVisible(false)` 직접 호출로 키보드 숨기기 확정 + 전체화면에
창닫기 버튼이 없어 앱 내 "종료" 확인 팝업 추가).

**발견한 버그와 원인**:
1. **QML 브레이스 누락** — `9774dbd`(다른 세션이 이미 push한 "safety mission and inspection
   dashboard" 커밋)의 경로계획 waypoint Repeater에서 `}`가 하나 빠져 있어 그동안 한 번도
   컴파일 성공한 적 없었던 것으로 보임. `e8b468d`에서 함께 수정.
2. **터치 두 개 동시 입력 불가** — 처음엔 QML 로직(MultiPointTouchArea) 문제로 의심했으나,
   `evtest`류 도구 없이 `libinput debug-events`로 커널 레벨 원시 터치 캡처 → **커널·드라이버는
   두 터치포인트를 정확히 동시 보고함**(하드웨어 문제 아님) 확인. 이어서
   `WAYLAND_DEBUG=1`로 Qt 클라이언트가 실제로 받는 프로토콜 이벤트를 봤더니 `wl_touch`가 아니라
   **`wl_pointer`(단일 마우스 포인터)로만 전달**되고 있었음. 원인은
   `~/.config/labwc/rc.xml`의 `<touch deviceName="10-0038 generic ft5x06 (79)"
   mapToOutput="DSI-1" mouseEmulation="yes"/>` — **`mouseEmulation="yes"`가 명시적으로 켜져
   있었음.** `"no"`로 바꾸고 `kill -HUP <labwc pid>`로 즉시 리로드 → 두 손가락 동시조작 확인됨.
   **이 항목이 이번 세션 최대 소득.**
3. **OS 가상 키보드 vs 커스텀 키보드 충돌** — 처음엔 커스텀 터치 키보드를 만들어뒀는데, 실제
   터치스크린에 연결하니 OS 자체 가상 키보드(squeekboard)까지 같이 떠서 중복 노출됨. 사용자가
   "OS 키보드를 쓸 거니 커스텀 키보드를 없애라"고 방향 전환 지시 → 커스텀 키보드 완전 삭제,
   `TextField`가 포커스 받으면 OS가 알아서 뜨도록 방치.
4. **전체화면(exclusive fullscreen)이 OS 키보드를 가림** — `visibility: Window.FullScreen`
   상태에서는 squeekboard가 아예 안 뜸(포커스는 잡히는데 오버레이가 안 보임) → 진짜 fullscreen
   대신 **frameless 창(테두리만 없애고 화면 크기에 맞춤)**으로 변경하니 키보드가 다시 뜸.
5. **데스크톱 상단 패널(wf-panel-pi) 제거의 부작용** — frameless 창으로 바꾸니 화면이 꽉 차긴
   했는데 상단 패널이 여전히 자리를 차지해 레이아웃이 눌림(사용자 표현: "뭉개진다") → 사용자
   autostart(`~/.config/labwc/autostart`)를 새로 만들어 `wf-panel-pi` 줄만 빼고 재부팅 없이도
   `pkill -9 -x wf-panel-pi`로 즉시 반영. **그런데 패널에 있던 "키보드 숨기기 토글" 버튼도 같이
   사라져서, 한 번 뜬 OS 키보드를 내릴 방법이 없어짐**(화면 절반을 가린 채 고정).
6. **키보드 숨기기 버튼이 안 먹고, 뒤의 비상정지가 대신 눌림** — 처음엔 앱에 `Qt.inputMethod.hide()`
   버튼을 추가했지만 안 먹혔고, 심지어 모달 팝업(`connectionPopup`) 뒤의 배경 위젯(비상정지
   버튼)이 터치됨 — Qt 모달 팝업이 이 터치 스택에서 배경 클릭을 확실히 막지 못하는 것으로 보여
   양쪽 팝업(`connectionPopup`, `missionPopup`) 콘텐츠 최상단에 `MouseArea { anchors.fill:
   parent }` 차단막을 명시적으로 깔아 배경으로 새는 걸 막음.
7. **`Qt.inputMethod.hide()`가 squeekboard를 실제로 못 내림** — squeekboard는 D-Bus 서비스
   `sm.puri.OSK0`(`/sm/puri/OSK0`, 메서드 `SetVisible(bool)`)를 직접 제공함. `dbus-send`로
   수동 호출해 확인 후, `DashboardBackend::hideOnScreenKeyboard()`(Qt6::DBus 추가,
   `QDBusInterface`로 호출)를 앱에 넣어 "키보드 숨기기" 버튼에 연결 — **이제 확실히 내려감.**
8. **frameless/fullscreen 앱을 끌 방법이 없음** — 창 테두리·닫기 버튼이 없어서 앱을 종료할 수
   없었음 → 상단 바에 "종료" 버튼 + 확인 팝업(`quitPopup`) 추가, `DashboardBackend::
   quitApplication()`(`QCoreApplication::quit()`) 연결.
9. **앱 재실행 수단 없음** — 종료 후 패널도 없어서 다시 켤 방법이 없었음 → `~/rpi4-dashboard/
   run.sh`(환경변수 설정 후 실행) + `~/Desktop/silorobot-dashboard.desktop` 바탕화면 바로가기
   생성. 첫 시도는 탭해도 무반응이었는데, 원인은 `~/.config/libfm/libfm.conf`의
   `single_click=0`(더블클릭 필요) — `single_click=1`로 변경. 단, `pcmanfm-pi`를 재시작해야
   반영되는데 실제 프로세스명이 `pcmanfm-pi`가 아니라 `pcmanfm --desktop`이라 `pkill -x
   pcmanfm-pi`가 안 먹혀 PID로 직접 kill 후 재기동해야 했음.

**SSH/배포 작업 팁 (재사용 가능)**:
- 백그라운드로 앱을 띄울 때 `cmd &` 뒤에 SSH 세션이 끊기면 죽는 문제가 있었음 → 원인은
  `loginctl show-user amc71 -p Linger`가 `no`였던 것 — **세션이 끝나도 그 사용자의 프로세스를

  직접 찾아 `kill`하는 쪽이 항상 더 안전함(자기 자신의 명령행과 우연히 매칭되는 사고 방지).

## Claude Code 세션 후속 — 영상 자동재생·키보드 대칭 제어·계획 화면 재설계

같은 날 이어서 사용자가 실사용하며 발견한 3가지를 추가로 수정. 커밋 `b0fff03`~`e5f0457`.

1. **계획(경로 생성) 화면이 "네모에 줄만" 있어 뭘 나타내는지 안 보이고, 사일로는 세로로 긴
   원통인데 도표가 가로로 넓은 정사각형이었음.** → "추천 경로 미리보기"·"사일로 전개도" 두
   패널을 세로로 긴(portrait) 박스로 다시 그림. 각 구간을 잇는 커넥터 선분을 추가해 지그재그가
   실제로 하나로 이어진 경로처럼 보이게 하고, 시작(주황 점)·종료(초록 점) 라벨을 붙임
   (`b0fff03`). **경로 생성 자체는 여전히 나노 B01 응답이 있어야 확인 가능 — 오늘은 화면 구성만
   다듬음, 실제 동작 미검증.**
2. **앱을 새로 켜면 영상이 저절로 안 뜨고, "연결 설정 → 저장 및 적용"을 눌러야만 나옴.** 원인은
   코드 로직이 아니라 **타이밍 경쟁** — 앱이 뜨는 시점에 나노 B01의 RTSP 서버가 아직 응답 준비가
   안 돼 있으면 첫 연결 시도가 조용히 실패한 채 멈추고, QtMultimedia가 자동 재시도를 안 함(저장
   버튼을 누르면 `rtspUrl`이 강제로 재설정되며 재연결되는 것뿐). → 재생 중이 아니면 4초마다
   `player.stop(); player.play()`로 재시도하는 Timer 추가(`eb1aea3`). 결과: 앱 켜면 별도 조작
   없이 약 5초 안에 영상 자동 연결됨(사용자 확인).
3. **OS 키보드(squeekboard)가 한 번 숨기면 다시는 안 뜨고, 뜬 상태에서는 화면 절반을 가려
   WebSocket 포트·계획 입력창이 아예 안 보임.**
   - 원인 A: squeekboard의 D-Bus `SetVisible(false)`는 **자동 모드로 되돌리는 방법이 없는
     일방향 수동 오버라이드**(`Visible` 프로퍼티는 읽기 전용, `SetVisible`만 있고 "리셋" 메서드
     없음 — D-Bus introspect로 확인). 한 번 `false`로 부르면 이후 포커스가 잡혀도 안 뜸.
   - 해결: 자동(포커스 트리거)에만 의존하지 않고, **모든 TextField의 포커스 변화에 맞춰
     `SetVisible(true/false)`를 매번 대칭으로 직접 호출**하도록 변경(`onActiveFocusChanged:
     dashboard.setOnScreenKeyboardVisible(activeFocus)`). 팝업 배경 빈 곳을 탭해도 포커스를
     끊고 숨기도록 처리(`075c6f1`).
   - 원인 B: 팝업이 화면 중앙에 뜨다 보니, 화면 하단을 차지하는 키보드와 겹침. → `connectionPopup`·
     `missionPopup`을 화면 상단 쪽으로 이동. **삽질**: `Popup.anchors`는 `centerIn`만 지원하고
     `top`/`topMargin`은 없음("Cannot assign to non-existent property") — `x`/`y`를 직접
     계산해서 지정하는 방식으로 수정(`e5f0457`).
   - 결과: 입력창 포커스 시 키보드 뜸, 다른 곳 탭하면 확실히 내려감, WebSocket 포트 필드도
     안 가림 — 사용자 실기 확인 완료.

## Claude Code 세션 3부 — 기록 뷰어 + 계획 화면 실통합 확인 + 핵심 버그 발견 (`e6c2047`~`24f38d5`)

**기록 뷰어 신설** (`e6c2047`): "점검 기록" 최근 3개만 보이던 걸로는 확인이 안 돼서, 앱 안에
전체 기록을 훑어보는 갤러리 팝업("기록 보기" 버튼) 추가. `DashboardBackend::loadAllRecords()`가
`records/YYYY-MM-DD/records.jsonl`을 전부 스캔해 반환, 왼쪽 목록 + 오른쪽 큰 미리보기 + 메타데이터
(안전상태·자세·거리·기록ID) 구성. 바탕화면에도 `점검기록` 심볼릭 링크 생성.

**점검 기록 캡처에 결함 박스 포함** (`b9137cd`): 기존엔 `videoOutput`만 캡처해서 화면에 뜬
결함 박스가 저장 이미지엔 안 찍혔음 — `VideoOutput`과 결함 박스 `Repeater`를 `captureFrame`이라는
공통 `Item`으로 묶고 이걸 `grabToImage`하도록 변경. 결함탐지가 실제로 붙으면 박스 포함 사진이
저장됨(오늘은 오린 미연동이라 미검증).

**앱 시작 시 키보드 자동 표시 문제** (`e8c5614`): 상단 버튼 중 아무거나 처음 누르면(팝업 종류
무관) 키보드가 뜸 — 원인은 창이 처음 키보드 포커스를 받는 순간 squeekboard가 "이 창엔 입력창이
있다"고 판단해 자동으로 뜨는 것. `Component.onCompleted`에서 앱 시작하자마자 명시적으로
`setOnScreenKeyboardVisible(false)`를 호출해 해결.

**QML 배열 변경 미감지 버그**: `missionPopup.planValues[5] = x`처럼 배열 원소만 바꾸면 QML이
바인딩 갱신 신호를 안 보내서, 실제로는 값이 바뀌어도 화면(테두리 강조 등)이 안 바뀜 — 배열을
통째로 복사해 재대입하는 `setPlanValue()` 헬퍼로 수정(`b2fabb6`). [[03. 트러블슈팅]] 참조.

**나노 B01 실통합 확인**: 사용자가 "B01 이제 연결 잘되는데"라고 알려줘서 실제로 접속해보니 —
`camera_rtsp_server`·`coverage_planner`·`dashboard_bridge` 등 8개 노드가 전부 떠 있고, 라파와
WebSocket도 `ESTABLISHED` 상태였음. 라파 대시보드에 이미 저장된 설정이 Tailscale 주소(임시
랜선 직결 IP 아님)였다는 것도 이때 재확인.

**"추천 경로 생성" 버튼이 반응 없는 것처럼 보였던 사건과 핵심 발견** (`a29be4a`):
- 처음엔 나노 B01의 `dashboard_bridge`가 CPU를 계속 쓰길래(21%) 무한루프로 의심 → 죽이고
  `PYTHONUNBUFFERED=1`로 재기동해보니 정상 연결·정상 로그 출력 확인, **오판이었음**(stdout

  흉내내며** 대시보드가 실제로 뭘 보내는지 지켜봄 → 버튼을 눌러도 **대시보드가 나노 쪽으로 아무

- 원인: **`requestRoutePlan` 버튼만 유일하게 `QtQuick.Controls Button`을 쓰고 있었음.** 이 화면의
  다른 모든 컨트롤(코너 선택, 키보드 숨기기, 종료 등)은 전부 `Rectangle + TapHandler` 패턴인데,

  `MouseArea`와의 상호작용 문제로 추정, 확정 원인 규명은 안 됨). `Rectangle + TapHandler`로
  바꾸니 즉시 해결.
- **중요**: 알고 보니 사용자는 이미 "누르면 전개도가 잘 나온다"고 여러 번 말했었는데, 진단자(나)가

  건 기능 수정이 아니라 그 결과 화면의 **디자인 개선**이었음.

## 6. `0xBC` 13바이트 프레임 검증

프레임 계약:

```text
[BC][02][left int32 LE 4B][right int32 LE 4B][flags][xor][55]
```

XOR 범위는 byte 1~10이며 송신 주기는 20Hz이다.

- [ ] 헤더 `BC`, 타입 `02`, 끝 `55`
- [ ] 정확히 13바이트
- [ ] 초당 약 20프레임
- [ ] 좌·우 값이 little-endian signed int32로 복원됨
- [ ] checksum이 byte 1~10 XOR과 일치
- [ ] bit0 좌측 유효, bit1 우측 유효
- [ ] 부팅 후 첫 프레임에 bit3 reset이 있고 이후 해제됨
- [ ] 기존 `0xBB` 8바이트 거리 프레임도 계속 20Hz로 수신됨

## 7. 거리센서 ADC 기준점 수집

### 10. STM32 ↔ Nano UART·대시보드 명령 통합


### 11. FT232 + WT901C IMU 확인

배선: FT232 전압 점퍼 **3.3V**, WT901C TX→FT232 RXD / RX←TXD, GND 공통. Nano USB 연결 후
`/dev/ttyUSB0`을 확인한다. 5V TTL은 연결하지 않는다.

```bash

ros2 topic echo /silorobot/imu_health
ros2 topic echo /silorobot/imu
```
