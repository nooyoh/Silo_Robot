## STM32 핀 재배치

- 좌·우 모터 제어선과 엔코더를 눈으로 구분되는 블록으로 재배치하고 TIM2를 예비로 비웠다.
- 정확한 최종 핀 표는 로그에 복제하지 않고 [[2. 하드웨어/05. 배선도]]만 사용한다.
- Nano↔STM32는 짧은 ST-LINK USB 한 가닥을 유지한다. Jetson 5V→NUCLEO E5V + GPIO UART도
  가능하지만 NUCLEO 납땜 브리지 변경과 IMU 포트 충돌이 있어 이번 조립에는 사용하지 않는다.

## F401RE 실물 플래시 완료

- ST-LINK가 `NUCLEO-F401RE`, Device ID `0x433`(STM32F401xD/E), 3.25V로 정상 인식됐다.
- `stm32-controller@4de305d` 기준 F401 바이너리(13.02KB)를 `0x08000000`에 기록했다.
- STM32CubeProgrammer의 download, verify, software reset이 모두 성공했다.
- **새 핀맵 펌웨어가 이미 들어갔다.** 모터전원은 계속 OFF로 두고, 다음은 단일 정본에 따른 12개 제어선 재배선과
  도통 검사다. 이전 배선 상태에서 모터전원을 켜지 않는다.

## Nano·RPi Tailscale 원격 배포

- Tailscale에서 Nano `ubuntu`(`100.121.144.38`)와 RPi `amc`(`100.74.141.112`)가 direct 연결,
  각각 7ms·10ms로 응답했다.
- Nano 작업 트리는 clean `main`이었으나 `154cae7`로 오래됐고 비공개 GitHub HTTPS 인증이 없어
  pull이 실패했다. Windows의 검증된 `ddf1b59` 전체 Git bundle을 전송해 원격 저장소 자체를
  fast-forward하고 임시 bundle은 양쪽에서 삭제했다.
- Nano `silorobot_nano` build 성공. sudo 비밀번호 없이 재기동하기 위해 `User=jetson`,
  `Restart=always`인 기존 프로세스를 정상 종료했고 systemd가 최신 코드로 자동 재기동했다.
  8개 노드 단일 실행, IMU 연결, RTSP `8554`, RPi WebSocket 연결을 확인했다.
- Nano에서 STM32 `/dev/ttyACM0`은 현재 보이지 않아 브릿지가 안전 재접속 대기 중이다. F401RE를
  Nano ST-LINK USB에 연결한 뒤 preflight를 다시 실행해야 한다.
- RPi는 `2746ea0→7a5c99c` fast-forward, Qt6 Release native build 성공. 사용자 systemd 자동실행을
  설치해 `silorobot-dashboard.service` active, 재시작 0회, `*:8765` 리슨을 확인했다.

## 전장 통합·모터 4개 구동 확인

- LRS-600-12의 12V `+V/-V`를 Y분기해 DFR0601 두 장의 `P+/P-`에 공급했다.
- STM32 명령과 LD2는 반응하지만 드라이버 채널 출력이 없던 원인은 DFR0601 제어전원이었다.
  NUCLEO `E5V`는 외부전원 입력이라 드라이버 전원 출력으로 쓸 수 없었다.
- 두 DFR0601의 제어 `VCC`를 NUCLEO `3V3`, 제어 GND를 NUCLEO GND에 연결하자 정상 출력됐다.
- PC COM6 직접 명령으로 모터 4개를 각각 확인했고, 빠진 모터 출력선 하나를 재체결한 뒤 네 개
  모두 회전했다. RPi→Tailscale→Nano→STM32 경로의 수동 명령에서도 LD2와 구동 반응을 확인했다.
- 실물에서 확정한 3.3V 제어전원은 [[2. 하드웨어/05. 배선도]]에 반영했다.

## 촬영용 계획 화면 연동 사각 주행 추가

- 커버리지 계획의 실물 동작이 미해결인 상황에서 영상 촬영을 진행할 수 있도록 Nano에
  `bash scripts/silorobot.sh demo-square`를 추가했다.
- 사용자 피드백에 따라 최종 동작을 **0.5 × 0.5m 계획 화면 + 10초 실행**으로 변경했다. RPi의
  기존 계획 실행 화면에 경로를 띄우고 현재 마커·방향·웨이포인트·진행률을 실물 명령과 동기화한다.
- 기본 타임라인은 직진 1.5초 ×4, 회전 0.6초 ×4, 구간 정지 0.2초 ×8로 정확히 10초다.
- 계획·오도메트리·거리/IMU 판단은 모터 제어에서 우회하고 RPi 비상정지와 STM32 300ms 명령
  타임아웃은 유지한다. 표시 좌표는 촬영용이므로 `0.5m 정밀주행`으로 표현하지 않는다.
- 실제 STM32 C 시험, 자율 폐루프, 통신·안전, 사각 시퀀스까지 전체 오프로봇 회귀검증을 통과했다.
- 영상·보고서 필수 촬영 항목은 [[12. 영상·보고서 촬영 체크리스트]]에 분리해 정리했다.

  실물 모터 명령을 약 10초 타임라인으로 동기화하도록 수정했다.

  `45339` 하나만 실행되도록 정리했다. Nano `dashboard_bridge`→RPi `8765` 연결은 `ESTABLISHED`.
- 배포용 임시 bundle과 일회용 SSH 키는 Nano·RPi·Windows에서 모두 제거했다.
