## 라즈베리파이(대시보드용) 재설정

- 기존 라파(hostname `amc`, 사용자 `amc71`)에 학교 실습용으로 쓰던 자료가 남아있어, 로봇용으로
  다시 밀기 전에 백업부터 진행.
- **백업**: SSH로 접속해 홈 디렉토리(`/home/amc71`, 총 3.4GB) 중 캐시/설치물성 폴더(`.cache`,
  `.oh-my-zsh`, `.local`, `.zcompdump*` 등) 제외하고 tar.gz로 압축(1015MB) → scp로 로컬 PC
  `C:\Users\5-21\Downloads\amc71_backup_20260814.tar.gz`로 다운로드 완료. 라파 `/tmp`의 사본은
  삭제. 백업 사유: "공부용으로 쓴 거라 세팅은 로봇용으로 다시 해야 함" — 즉 이 백업은 과거 학습
  자료 보관용이고, 새 라파 환경은 이 백업을 기준으로 복원하지 않음(처음부터 새로 구성).
- **OS 재설치**: Raspberry Pi Imager로 Raspberry Pi OS (64-bit, Debian Trixie, Desktop) 새로
  설치. hostname `amc`, 사용자 `amc71`, SSH 비밀번호 인증 활성화로 사전 설정.
- **네트워크 이슈**: 굽고 나서 `amc`/`amc.local`로 mDNS가 안 잡힘 → 원인은 두 가지 겹침
  1) 라파가 처음에 GUI 첫부팅 마법사(Welcome Wizard)에서 대기 중이라 네트워크/SSH 설정이 아직
     반영 안 된 상태였음 (헤드리스로 넘어가려 했으나 실제로는 GUI 진행이 필요했음)
  2) 현재 위치가 학교 실습실 네트워크(172.20.32.0/24, 다수의 기기·다른 팀 라즈베리파이 공존)라
     PC 이더넷과 라파 이더넷이 서로 다른 스위치/VLAN을 탈 가능성이 있어 mDNS/서브넷 스캔이 잘 안 됨
  3) 실제로는 GUI 마법사를 끝까지 진행하고 라파 자체 터미널에서 `hostname -I`로 IP(172.20.32.49)
     확인 → 그 IP로 SSH 접속 성공. 이후 로컬 PC의 SSH 공개키를 라파
     `~/.ssh/authorized_keys`에 등록해 비밀번호 없이 접속 가능하게 함.
  4) 첫 부팅 시 hostname이 `raspberrypi`로 나와 Imager 설정이 반영 안 된 걸 확인 → `hostnamectl
     set-hostname amc` + `/etc/hosts` 수정으로 수동 정정.
- **업데이트**: `sudo apt update && sudo apt full-upgrade -y` 완료 (커널 6.18.34 → 6.18.39,
  initramfs 재생성 포함). 재부팅 필요.
- 이후 `ssh amc71@amc` 접속 시 호스트 키가 바뀌었다는 경고 발생 — OS 재설치로 인한 정상적인 변경
  (MITM 아님), `ssh-keygen -R amc`로 기존 known_hosts 항목 제거 후 재접속.
