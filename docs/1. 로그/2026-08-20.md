## 2026-08-20 SOL 코드 관제 재점검

### 시뮬레이션·정적검사 결과

- STM32 순수 C 코어 테스트 통과: 프로토콜 checksum, STOP 래치/해제, 300 ms timeout,
  모터 혼합·slew·deadzone, 거리 LUT, 16/32비트 엔코더 wrap, `BB`·`BC` 프레임.
- Nano Python 14개 및 전체 Python 22개 AST 검사 통과.
- Orin detection message 테스트와 전체 AST 검사 통과.
- 통합 모의시험 통과: 12×8 m, 점검폭 0.4 m, 중첩 20%, 여백 0.2 m 조건에서
  48 waypoint 생성; UART 잡음·분할 수신 상태에서 `BB`+`BC` 복원; 경로 pause→resume→cancel;
  AUTO 중 수동 move 차단과 cancel 뒤 수동 move 복구.
- Windows에는 Qt/CMake·ARM GCC가 없고 RPi4 `amc` SSH도 timeout이라 RPi native build와
  F401/F411 cross build는 이번 점검에서 실행하지 못했다. 물리장비 확인 항목으로 유지한다.

### 발견 후 수정한 문제

- `route_resume`이 `READY`에서만 허용되어 실제 pause 뒤 재개가 불가능하던 상태 조건 수정.
- dashboard_bridge와 path_follower가 AUTO 중 같은 `/drive_command`를 발행할 수 있던 충돌 수정.
  `mission_state.mode`를 추적하고 AUTO 동안 대시보드 수동 move를 버린다.
- pause/cancel 때 0 명령을 즉시 발행해 UART 300 ms timeout을 기다리지 않도록 수정.
- STM32·UART bridge는 부팅 래치인데 safety supervisor만 해제 상태로 시작하던 불일치 수정.
  supervisor도 `latched=true`로 시작한다.
- RPi 계획 팝업의 0.8초 가짜 진행 Timer 제거. 실제
  `route_plan_request → /plan → mission_state → status WebSocket → RPi` 왕복으로 연결.
- RPi에서 IMU가 정확히 0도일 때 `--`로 표시되던 공용 숫자 변환 수정. 거리 0만 미수신으로 취급.
- 해제 요청 직후 이전 safety reason을 보고 즉시 거부 표시하던 race 수정.
  Nano의 명시적 `release_rejected`가 도착할 때만 거부로 확정한다.
- 비상정지 버튼의 로컬 토글을 제거했다. 정지 요청은 즉시 보수적으로 표시하되, 해제 표시는 Nano
  status의 실제 `safety.latched=false`가 수신돼야만 바뀐다.
- Orin의 0 FPS/잘못된 confidence·image size와 빈 추론 결과 처리 보강.

### 실행 전 안전 차단 조건

- STM32 거리 LUT는 아직 0이며 safety supervisor는 정지 래치 해제에 최신 유효 거리 2개를 요구한다.
  따라서 **현재 안전 기본값으로는 센서 보정 전 모터 해제가 거부되는 것이 정상**이다.
- 센서 없는 벤치시험용 우회는 물리 안전 인터록 완화이므로 자동 반영하지 않았다. 화요일에는 먼저
  거리센서 LUT를 채우거나, 별도 명시 승인 후 제한된 bench-release 설계를 추가한다.
- `armed=false`는 자동 센서 정지만 비활성화할 뿐, 수동 STOP 래치 자체를 우회하지 않는다.

## 추정 기본 프로파일 입력 및 2중 재검증

실측값이 0이라 기능 전체가 막히는 대신, **튜닝 시작점용 추정값**을 코드에 넣었다. 추정값을 실측값으로
오인하지 않도록 거리센서는 `calibrated=false`, `calibration_source=DATASHEET_ESTIMATE`를 유지한다.

| 항목 | 입력 기본값 | 산출 근거 | 실측 후 교체 |
|---|---:|---|---|
| 거리 ADC LUT | 20/30/50/70/100/120/150mm → 3288/2605/1675/1179/807/645/496 | GP2Y0A51SK0F 전형 출력곡선, 3.3V·12bit 환산 | 센서별·거리별 30회 이상 중앙값 |
| 엔코더 count/rev | 18,560 | 16PPR × 290 × x4 가정 | 출력축 10회전 누적 count ÷ 10 |
| 궤도 유효 이동/rev | 0.2686846m | 제공 STL 구동륜 추정 피치지름 85.525mm | 직진 1m ×5의 실제 count/m |
| meters/count 좌·우 | 0.000014476541 | 0.2686846 ÷ 18,560 | 실제 이동거리 ÷ count |
| track width | 0.30m | 기구 미확정 보수 추정 | 제자리 360° ×5 오차로 유효값 보정 |
| PWM 유효 범위 | 120~700 permille | 20%에서 이미 회전한 실측 + 초기 출력 제한 | 무부하/부하 최소기동과 최대안전 출력 |
| 경로추종 최대값 | 전진 15%, 회전 20% | 초기 저속 시험용 | 평면 저속 튜닝 후 단계 상승 |
| 거리 편차 warn/stop | 15/30mm | 2~15cm 센서 범위 내 보수 시작점 | 평행·경사·한쪽 들림 데이터 분포 |
| 거리 증가율 stop | 120mm/s | 급격한 전체 이격 시작점 | 정상 전환/이탈 로그 분포 |
| 각속도 warn/stop | 60/120°/s | 저속 기체의 급회전 시작점 | 완만 회전과 급흔들림 로그 분포 |
| 가속도 편차 | 0.35g | 충격 보조조건 시작점 | 정지/주행/충격 로그 분포 |
| 시작/해제 안정시간 | 1500/500ms | 부팅·센서 초기 안정화 | 실제 연결 안정시간 |

- `distance_calibration_confirmed:=false`가 기본이다. 데이터시트 LUT만으로는 STOP 해제가 안 된다.
- 센서별 실측 LUT 교체 후에만 `distance_calibration_confirmed:=true`로 실행한다.
- `armed:=false`가 기본이므로 추정 안전 임계값은 자동 STOP에 사용되지 않는다.
- 해제 요청이 거부되면 Nano 내부 요청도 즉시 취소한다. 센서가 나중에 정상화돼도 이전 요청으로
  갑자기 해제되지 않으며, 사용자가 다시 눌러야 한다.

  Bash 구문·Python AST·package.xml 검증 통과

> 공식 곡선 LUT도 여전히 백지 기준 시작값이다. 실제 철판에서 센서 3개를 각각 측정하기 전에는
