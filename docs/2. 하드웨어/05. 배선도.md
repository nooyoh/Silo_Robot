> ① 전원 OFF 상태에서 전 결선 육안 검사 ② 모든 GND 공통 확인 ③ 엔코더 VCC가 **3.3V**인지

## 1. 전체 구성

```text
                    ┌─────────────────┐
   CSI 리본 ────────│  Jetson Nano B01 │───── USB ──→ 무선랜(Wi-Fi)
   (카메라)          │   "로봇 두뇌"     │
                    └───┬────────┬────┘
              GPIO UART │        │ USB (ST-LINK VCP)
              ttyTHS1   │        │ ttyACM0 · 115200bps
                        │        │  · 전원 + 통신 겸용
                 ┌──────┴───┐    │
                 │ FT232 불필요│   │      ※ IMU는 나노 GPIO에 직결
                 │ WT901C IMU │   │        (FT232 경유 안 함)
                 └──────────┘    │
                                 │
                    ┌────────────┴──────────┐
                    │  STM32 NUCLEO-F401RE   │
                    │   "실시간 모터 제어"     │
                    └──┬──────┬────────┬─────┘
              PWM/방향 │      │ ADC    │ 엔코더 AB
                 ┌─────┴──┐ ┌─┴────┐ ┌─┴──────────┐
                 │DFR0601 │ │거리   │ │ 엔코더 2개  │
                 │  ×2     │ │센서×3 │ │(좌M1·우M3)│
                 └───┬────┘ └──────┘ └────────────┘
                     │
              모터 4개 (좌2·우2)
```

**역할 분리**: STM32는 모터 실시간 제어와 아날로그 센서(거리·배터리)만, 나노는 그 외 전부.
거리센서가 STM32에 붙는 이유는 나노 B01에 ADC가 없기 때문이다 ([[02. 결정로그]]).

### Nano ↔ STM32 전원·통신 방식

**현재 확정 배선은 짧은 ST-LINK USB 한 가닥이다.** 이 한 가닥이 NUCLEO 전원과
`/dev/ttyACM0`(USART2, 115200bps) 통신을 동시에 해결하고, Nano 40핀 UART는 WT901C IMU가
계속 사용한다. 아크릴판 위에서는 긴 USB 케이블을 감지 말고 15~30cm 짧은 데이터 케이블과
케이블타이 고정점을 쓴다.

USB를 없애는 아래 방식도 전기적으로 가능하지만 **현재 조립에는 비권장 대안**이다.

| Jetson Nano 40핀 | NUCLEO-F401RE | 용도 |
|---|---|---|
| pin 2 또는 4 (5V) | **CN7 pin 6 E5V** | NUCLEO 외부 5V 전원 |
| GND | GND | 공통 접지 |
| pin 8 TX | D0 / PA3 RX | Nano → STM32 UART |
| pin 10 RX | D1 / PA2 TX | STM32 → Nano UART |

> [!warning] 점퍼선 네 가닥만 꽂으면 되는 방식이 아니다
> NUCLEO는 JP5를 E5V(2-3), JP1 제거로 설정해야 하고, USART2를 D0/D1에 연결하려면
> **SB13·SB14 OFF / SB62·SB63 ON 납땜 작업**이 필요하다. 이때 ST-LINK VCP는 사용할 수 없다.
> 또 pin 8/10은 현재 IMU와 겹치므로 IMU를 FT232 USB(`/dev/ttyUSB0`)로 옮겨야 한다.
> Arduino `+5V` 핀을 외부 전원 입력으로 쓰거나 USB와 E5V를 무계획하게 동시에 물리지 말 것.

## 2. 모터 장착 방향 (2026-08-22 확인)

웜기어 모터가 **누워서** 장착되고, **같은 쪽(좌측끼리·우측끼리) 앞뒤 모터의 엔코더 단이
서로 마주본다.**

```text
        ── 로봇 앞쪽 ──
   좌앞 M1 ↓        ↓ 우앞 M3      ↓↑ = 엔코더 단이 향하는 쪽
   (엔코더)          (엔코더)          (같은 쪽끼리 마주봄)

   좌뒤 M2 ↑        ↑ 우뒤 M4
        ── 로봇 뒤쪽 ──
```

**전기적 결론 — 추가 반전 불필요.** 마주보게 장착돼 있어도 **현재 배선에서 같은 쪽 두 모터는
같은 방향으로 돈다**(사용자 실물 확인). 즉 방향 보정이 이미 배선에 반영돼 있다.
좌우 정렬도 확인됨: **`turn=+`(우회전) 명령 시 좌측 궤도 전진·우측 궤도 후진.**

> 펌웨어는 같은 쪽 두 모터에 **똑같은 신호**를 보낸다(`silo_motor_driver.c`의
> `motor[0]=motor[1]=left`, `motor[2]=motor[3]=right`). 그러므로 같은 쪽 두 모터가 반대로
> 도는 상태로 배선하면 두 모터가 서로 싸우면서 궤도가 안 움직이거나 과전류가 난다.
> **모터를 다시 달거나 커넥터를 바꿔 끼웠다면 §8 검증 절차를 반드시 다시 돌릴 것.**

## 3. STM32 ↔ 모터 드라이버 (DFR0601 ×2)

DFR0601 **#1이 좌측 궤도(M1·M2)**, **#2가 우측 궤도(M3·M4)** 를 담당한다.
채널마다 `PWM`·`INA`·`INB` 3선이 필요하고, PWM은 **20kHz**(DFR0601 권장 18~60kHz 내).

| 모터     | 위치          | PWM           | 타이머      | INA           | INB           |
| ------ | ----------- | ------------- | -------- | ------------- | ------------- |
| **M1** | 좌 앞 (엔코더 有) | **D5** (PB4)  | TIM3_CH1 | **D2** (PA10) | **D3** (PB3)  |
| **M2** | 좌 뒤         | **D9** (PC7)  | TIM3_CH2 | **D4** (PB5)  | **D6** (PB10) |
| **M3** | 우 앞 (엔코더 有) | **D10** (PB6) | TIM4_CH1 | **D11** (PA7) | **D12** (PA6) |
| **M4** | 우 뒤         | **D14** (PB9) | TIM4_CH4 | **D13** (PA5) | **D15** (PB8) |

**배선 묶음:** 좌측 제어는 D2~D6에 모으고 M2 PWM만 D9를 쓴다. D7/D8은 좌측 엔코더다.
우측 제어는 D10~D15를 순서대로 쓴다. 좌·우 드라이버마다 6가닥 리본/듀퐁 묶음으로 만들고
양 끝에 `L-M1`, `L-M2`, `R-M3`, `R-M4` 라벨을 붙인다.

> [!warning] 2026-08-24 이전 배선과 호환되지 않는다
> 새 펌웨어 플래시와 위 12선 재배선을 한 세트로 수행한다. 한쪽만 먼저 적용하면 잘못된 모터가
> 움직일 수 있으므로, 재배선이 끝날 때까지 모터 전원은 OFF로 둔다.

### DFR0601 제어 논리

| INA | INB | PWM | 출력 |
|---|---|---|---|
| L | L | 무관 | 정지 |
| L | H | 듀티 | 정방향 |
| H | L | 듀티 | 역방향 |
| H | H | 무관 | 플로팅(Hi-Z) |

- **NUCLEO GND ↔ DFR0601 제어부 GND는 반드시 공통 접지.**
- **DFR0601 두 장의 제어부 `VCC`는 NUCLEO `3V3`에 연결한다.** 2026-08-24 실물에서
  3.3V 제어전원으로 네 채널 구동을 확인했다. NUCLEO의 `E5V`는 외부 전원 입력이므로 여기에
  연결해 드라이버 전원을 공급하려 하지 않는다.
- 모터 전원은 별도 12V 전원의 `+V/-V`를 각 드라이버 `P+/P-`에 연결한다. 제어부 `VCC/GND`와
  모터 전원 `P+/P-`를 혼동하지 않는다.
- `STATE`는 보드 상태 LED — MCU 입력으로 쓰지 않는다.
- 방향 즉시 반전 금지. 펌웨어가 약 100ms 감속 램프로 PWM 0을 거쳐 역전시킨다.
- 비상정지·통신 타임아웃(300ms)은 램프 없이 즉시 `PWM=0, INA=L, INB=L`.
- **PA5(D13)는 보드 LD2 녹색 LED와 공유** — M4 방향에 따라 LED가 같이 켜지나 무해.
- PB3(D3)의 기본 기능은 SWO(디버그 트레이스). SWD 플래시·디버깅엔 영향 없음(SWO 미사용).

## 4. 엔코더 (WGM40-3150-1280E, AB 2상 16PPR)

**좌·우 각각 앞쪽 모터에만** 장착. 나머지 2개는 엔코더 고장으로 사용하지 않는다.
하드웨어 엔코더 모드 타이머를 쓴다.

| 위치 | 신호 | 핀 | 타이머 | 카운터 |
|---|---|---|---|---|
| 좌 (M1) | A | **D7** (PA8) | TIM1_CH1 | 16비트 (SW로 int32 누적) |
| 좌 (M1) | B | **D8** (PA9) | TIM1_CH2 | 16비트 |
| 우 (M3) | A | **A0** (PA0) | TIM5_CH1 | **32비트** |
| 우 (M3) | B | **A1** (PA1) | TIM5_CH2 | **32비트** |

### 커넥터 (XH2.54 6핀)

```text
1: 모터 +    ← 드라이버 출력으로. MCU에 연결 절대 금지
2: 모터 −    ← 드라이버 출력으로. MCU에 연결 절대 금지
3: Hall GND  → STM32 GND (공통)
4: Hall VCC  → STM32 3.3V  ★ 5V 금지 (A/B 출력도 5V가 되어 입력 과전압)
5: A Vout    → 위 표의 A핀
6: B Vout    → 위 표의 B핀
```

### 왜 TIM1·TIM5인가

LQFP64에서 엔코더 모드(CH1·CH2 동시)가 가능한 타이머는 사실상 이 둘뿐이다.

| 타이머 | 판정 |
|---|---|
| TIM3 / TIM4 | PWM 4채널에 이미 사용 중 |
| TIM2 | 현재 미사용(예비) |
| TIM9 (PA2/PA3) | 현재 권장 USB VCP 모드의 USART2와 충돌 |
| TIM10 / TIM11 | 단일 채널이라 엔코더 모드 불가 |
| **TIM1** (PA8/PA9) | 채택 |
| **TIM5** (PA0/PA1) | 채택. 32비트라 랩어라운드 부담 없음 |

현재 전체 배정은 §3·§5·§9 표를 함께 따른다.

### 부호 규약 (2026-08-21 실측 확정)

- **양쪽 모두 "카운트 감소 = 전진"** → `meters_per_count_left/right` 둘 다 **음수**
- **좌우 스케일 부호는 반드시 함께 뒤집을 것.** 한쪽만 뒤집으면 제자리 회전이 "직진"으로
  적분되어 회전각이 0으로 붕괴한다 ([[03. 트러블슈팅]] 2026-08-21 밤 항목)
- 이 부호는 `path_follower`의 조향 부호와 **한 쌍**이다. 하나만 바꾸면 조용히 발산한다.
- **배선을 바꿨으면**: `ros2 run silorobot_nano verify_signs` → 전진 한 번·우회전 한 번 밀면
  두 부호를 자동 판정해준다.

## 5. 거리센서 3개 (SHARP GP2Y0A51SK0F) — **미배선**

| 센서 | 핀 | ADC 채널 |
|---|---|---|
| d1 | **A2** (PA4) | ADC1_IN4 |
| d2 | **A3** (PB0) | ADC1_IN8 |
| d3 | **A4** (PC1) | ADC1_IN11 |

> A0/A1에서 A3/A4로 이동했다(PA0/PA1이 엔코더용). 미배선이라 이동 비용 없음.
> d1·d2·d3와 물리적 좌·중·우 대응은 **배선할 때 정하고 이 문서에 적을 것.**

### 센서 1개당 결선

```text
센서 Vcc ──┬── NUCLEO 5V
           │
        0.1uF        ← 센서 바로 옆 (전원 디커플링)
           │
센서 GND ──┴── NUCLEO GND (공통)

센서 Vo ──[ 10kΩ ]──┬── NUCLEO A2 / A3 / A4
                    │
                 0.1uF      ← MCU 쪽 (RC 저역통과, fc ≈ 159Hz)
                    │
                   GND
```

- 커넥터는 3핀 JST, 순서는 **Vo / GND / Vcc**. 동봉 케이블 사용.
- **Vcc는 5V.** 5V일 때 출력이 대략 0.3V(15cm)~2.5V(2cm)로 3.3V를 안 넘어 ADC 직결 가능.
- **단, 첫 연결 전 멀티미터로 확인할 것.** 가장 가까운 거리(2cm)에서 Vo가 3.3V 미만인지
  눈으로 보고 나서 MCU에 물린다. 넘으면 분압을 넣어야 한다.
- RC 필터가 없으면 값이 심하게 튄다(내부 IR LED 펄스 구동 때문).
- **10kΩ을 넣으면 ADC 샘플링 시간을 늘려야 한다** — `ADC_SAMPLETIME_480CYCLES`(한 줄).
- 데이터시트는 Vcc-GND 간 10uF 이상 바이패스 권장. 0.1uF로 시작하고 계속 흔들리면 추가.

## 7. Jetson Nano B01 결선

### 7-1. IMU (WT901C, UART 버전) — GPIO 직결

WT901C는 핀 4개짜리 TTL-UART 모듈이라 USB 커넥터가 없다. **FT232 없이 나노 40핀 헤더에
직결**한다(FT232는 구매해뒀으나 이 구성에선 불필요).

```text
WT901C          Jetson Nano 40핀
──────          ────────────────
TX      ──────→ 핀 10 (UART RX)
RX      ←────── 핀  8 (UART TX)     ★ TX/RX 교차
VCC     ──────→ 핀  1 또는 17 (3.3V) ★ 5V(핀2/4) 금지
GND     ──────→ 핀  6/9/14/20 등
```

- 장치 노드: **`/dev/ttyTHS1`**, 9600bps
- **`nvgetty` 서비스를 꺼야 한다** — 이 포트를 시리얼 콘솔로 점유해 권한 거부가 난다:
  `sudo systemctl disable --now nvgetty` 후 재부팅
- 사용자가 `dialout` 그룹에 있어야 함: `sudo usermod -aG dialout jetson` 후 재로그인
- 확인: `ros2 topic echo /silorobot/imu_health` → `connected/valid=true`,
  `types_seen`에 `0x51`·`0x52`·`0x53` 모두 존재

### 7-2. STM32 (USB 1개로 전원+통신 겸용)

- NUCLEO 내장 ST-LINK의 가상 COM 포트 이용 → 나노에서 **`/dev/ttyACM0`**, 115200bps
- `dialout` 그룹 필요(위와 동일)
- 별도 UART 배선 불필요 — **USB 케이블 하나면 끝**

### 7-3. 카메라

- CSI 리본 커넥터 직결 → GStreamer `nvarguscamerasrc` → RTSP 720p30

## 8. 배선 후 검증 절차

배선을 새로 하거나 바꿨으면 **순서대로** 확인한다. 모터 전원은 마지막에 넣는다.

### 8-1. 전원 OFF 상태
- [ ] 전 결선 육안 검사, 단락 없음
- [ ] STM32·드라이버·센서·파워서플라이 **GND 전부 공통**
- [ ] 엔코더 VCC가 **3.3V**인지 실측 (5V면 즉시 중단)
- [ ] 거리센서 Vo 최대값이 3.3V 미만인지 실측 (배선했다면)
- [ ] 좌측 제어선 D2~D6+D9, 좌 엔코더 D7/D8, 우측 제어선 D10~D15인지

### 8-2. 모터 전원 OFF, 로직만 인가
- [ ] 부팅 직후 모터 정지 상태 유지(펌웨어 정지 래치)
- [ ] `/dev/ttyACM0`·`/dev/ttyTHS1` 둘 다 보임
- [ ] `ros2 topic echo /silorobot/stm32_connected` → `true`
- [ ] 엔코더: 궤도를 손으로 못 돌리면(웜기어 자체잠김) 이 단계는 건너뛰고 8-3에서 확인

### 8-3. 궤도를 공중에 띄우고 모터 전원 ON
- [ ] 주변에 사람·케이블·공구 없음
- [ ] **같은 쪽 두 모터가 같은 방향으로 도는지** (반대면 그쪽 하나의 `M_A`/`M_B` 교체)
- [ ] `throttle=+`에서 **좌우 궤도가 로봇을 같은 방향으로 미는지**
- [ ] `turn=+`(우회전)에서 **좌 전진·우 후진**인지
- [ ] `ros2 run silorobot_nano verify_signs` → 전진 한 번·우회전 한 번 밀어서
      **두 부호 모두 "정상"** 판정 확인

### 8-4. 계측 (오실로스코프)
- [ ] PWM 4채널 모두 약 20kHz(주기 50µs): M1=D5, M2=D9, M3=D10, M4=D14
- [ ] 20%·50%·100% 명령에 High 폭이 비례
- [ ] 방향 전환 시 PWM이 0을 거친 뒤 반대로 증가
- [ ] 명령 중단 후 **300ms 초과 시 PWM 0** (페일세이프)

## 9. Arduino 헤더 사용 현황 (전부 소진)

```text
D0  PA3  VCP RX                    A0  PA0  엔코더 우 A (TIM5_CH1)
D1  PA2  VCP TX                    A1  PA1  엔코더 우 B (TIM5_CH2)
D2  PA10 M1 INA                    A2  PA4  거리 d1        (미배선)
D3  PB3  M1 INB                    A3  PB0  거리 d2        (미배선)
D4  PB5  M2 INA                    A4  PC1  거리 d3        (미배선)
D5  PB4  M1 PWM                    A5  PC0  배터리 #1      (미배선)
D6  PB10 M2 INB
D7  PA8  엔코더 좌 A (TIM1_CH1)
D8  PA9  엔코더 좌 B (TIM1_CH2)
D9  PC7  M2 PWM
D10 PB6  M3 PWM
D11 PA7  M3 INA
D12 PA6  M3 INB
D13 PA5  M4 INA (보드 LD2 LED 공유)
D14 PB9  M4 PWM (TIM4_CH4)
D15 PB8  M4 INB
```

**Arduino 헤더는 전부 찼다.** 추가 기능은 모포 헤더(CN7/CN10)를 쓴다.
