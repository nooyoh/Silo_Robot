## 보관용 대체 작성안 — 8/24 현재 사용하지 않음

> 아래는 기구 조립이 마감 전 불가능할 때 작성했던 대체안이다. 8/24 궤도·프레임 기구 조립이
> 완료됐으므로 제출본에는 사용하지 않는다. 전장 탑재·부하 주행·벽면시험이 남았다는 사실만 현재 문안에 반영한다.

공고문은 미완성 프로젝트도 **최종목표를 기준으로 작성하되 현재 진도와 추후 개발계획을 명확히
표시**하도록 허용한다. 부품 배송 지연으로 8/25 전 최종 조립이 불가능하면 아래 원칙을 적용한다.

### 작성 원칙

- 최종 조립·벽면 등반·부하 주행을 완료한 것처럼 표현하지 않음
- 3D 프린팅 완료, 소프트웨어 구현, 전장 벤치 구동, 전체 제어 경로, 실시간 영상을 각각 증빙
- 미도착 부품의 품명·주문일·예상 도착일과 조립·시험 예정일을 표로 제시
- `완료`, `검증 완료`, `진행 중`, `부품 입고 대기`, `조립 예정` 상태를 기능별로 명확히 구분
- 최종 목표 시스템 구성도와 현재 벤치 구성도를 나란히 배치해 차이를 숨기지 않음
- 단순 무선 조종이 아니라 `영상 관제 + 자세 인지 + 3점 거리 인지 + 안전정지`가 결합된 점검 시스템으로 설명
- IMU·거리센서는 실물 보유와 연결 설계를 근거로 작성하되, 실제 값 수신 전에는 `연동 완료`로 표기하지 않음

### 보고서에 바로 넣을 현재 상황 문안

○ 현재 개발 현황

- 상용 주행 플랫폼을 사용하지 않고, 곡률 적응형 궤도·자력 부착 구조·구동부를 직접 설계하여 3D 프린팅 완료
- STM32 모터 제어 펌웨어와 Nano B01·RPi4 관제 소프트웨어 구현 완료
- RPi4 관제 콘솔→Nano B01→STM32→모터 4개 전장 벤치 통합 제어 검증 완료
- Nano B01 CSI 카메라 영상의 RPi4 관제 콘솔 실시간 송출 검증 완료
- WT901C 9축 IMU와 SHARP 거리센서 3개 확보 및 센서 데이터 경로 설계 완료
- IMU는 Nano B01 UART 직결, 거리센서 3개는 STM32 ADC 수집 후 Nano B01로 전달하도록 구성
- 최종 프레임 조립에 필요한 일부 부품 배송 지연으로 기구 조립·부하 주행·벽면 등반 시험 대기
- 조립 전 센서 벤치에서 IMU 자세 변화와 3점 거리 변화의 실시간 수집·관제 표시를 우선 검증
- 조립 전 실제 모터·엔코더를 포함한 HIL 벤치에서 경로계획→모터명령→엔코더 피드백→가상 pose·
  waypoint 전환의 폐루프를 검증
- 미도착 부품 입고 후 기구 조립→최종 전장 배선→센서 임계값 조정→평면 주행→철판 부착·등반 순으로 시험 예정

○ 배송 지연 대응

- 기구 조립과 독립적으로 수행 가능한 펌웨어·통신·카메라·관제 기능을 선행 개발
- 모터와 제어기를 벤치 배선하여 완성 로봇과 동일한 제어 경로를 사전 검증
- IMU를 손으로 기울이는 자세 시험과 거리센서 3점 앞의 평판·곡면 이동 시험을 조립과 독립적으로 수행
- 3D 출력물의 조립 위치·체결 관계를 CAD와 실물 배치 사진으로 확인
- 부품 도착 즉시 조립할 수 있도록 배선도·핀맵·시험 순서 사전 확정

### 조립 불가 시 사진 구성

1. 3D 출력 부품을 조립 순서대로 펼친 전체 사진
2. CAD 조립도와 실제 출력물을 같은 방향으로 배치한 비교 사진
3. 모터 4개·드라이버·STM32·Nano B01의 전장 벤치 전체 사진
4. RPi4 조작으로 모터 4개가 회전하는 장면의 연속 캡처
5. IMU를 기울였을 때 관제 화면의 Roll·Pitch·Yaw가 변하는 비교 사진 `【실측 연동 후】`
6. 거리센서 3개 앞에서 평판·곡면 위치를 바꿀 때 세 값이 달라지는 비교 사진 `【실측 연동 후】`
7. Nano CSI 카메라 피사체와 RPi4 실시간 영상이 한 프레임에 보이는 사진
8. `최종 목표 구성도`와 `8/25 현재 구현 구성` 비교도
9. 최종 목표 형상 CAD·커버리지 경로·실제 모터 벤치·엔코더 기반 가상 pose가 함께 보이는 HIL 화면

### 조립 불가 시 진척도 작성 기준

- 진척도는 임의로 높이지 않고 기능별 완료 여부를 기준으로 산정
- SW: 코드 작성만이 아니라 실기 연결·동작 확인 여부까지 반영
- HW: 구매·출력과 조립·배선·실주행을 분리하여 산정
- 정확한 백분율은 미도착 부품과 실제 조립 상태를 확인한 뒤 기재
- 100% 미만 항목에는 반드시 완성 예정일 병기

### 조립 없이 가능한 핵심 검증 시나리오

| 검증 항목 | 조작·입력 | 확인 화면 | 보고서 표현 기준 |
|---|---|---|---|
| 무선 제어 | RPi4 터치로 전진·후진·조향 | 모터 4개 방향·속도 변화 | 전체 제어 경로가 실제 동작한 경우만 `검증 완료` |
| 영상 관제 | CSI 카메라 앞 피사체 이동 | RPi4 실시간 영상 | 실영상 지연 없이 확인한 경우 `실시간 송출 완료` |
| IMU 자세 | 센서를 수평·좌우·앞뒤로 기울임 | Roll·Pitch·Yaw 변화 | 실제 값이 RPi4까지 들어온 경우 `실측 연동 완료` |
| 3점 거리 | 센서 앞 평판을 평행·경사지게 이동 | d1·d2·d3 값과 편차 변화 | mm 보정 전에는 `ADC 변화 확인`, 보정 후 `거리 측정` |
| 안전정지 | 모터 구동 중 비상정지 터치 | 모터 출력 차단·정지 유지 | 해제 전 재구동되지 않는 것까지 촬영 후 `검증 완료` |

- 위 다섯 장면을 `움직임·시야·자세·거리·정지`로 묶어 최종 조립 없이도 시스템 통합성을 제시
- IMU·거리센서 값 변화와 모터 제어를 자동으로 결합하지 않았다면 `센서 기반 자동제어`로 표현하지 않음
- 현재 단계의 센서는 운용자 판단을 지원하는 상태 모니터링이며, 자동 감속·정지는 후속 개발 계획으로 구분

### 2. 주요 적용 기술

#### 1) 기능 구현 시나리오

○ 정상 점검 시나리오

- 운용자가 관제 콘솔에 사일로 지름·점검 높이·카메라 점검폭·중첩률을 입력하면, 측면 전개도 위에 지그재그 커버리지 경로를 생성하고 총 이동거리·회전횟수를 비교해 경로안을 제시
- 로봇을 벽면 하단에 부착하고 자석 위치를 조절해 부착력을 설정한 뒤, 관제 콘솔에서 연결·영상·센서 상태를 확인
- 경로 추종을 시작하면 좌·우 앞 모터 엔코더로 이동거리를, IMU 자이로로 회전각을 갱신하며 waypoint를 순차 통과
- 주행 중 CSI 카메라 영상이 실시간 송출되고, Orin이 동일 영상에서 균열을 탐지해 좌표만 관제 콘솔에 전달

○ 이상 발생 시나리오

- 한쪽 궤도가 들리면 3점 거리 편차가 커지고 IMU 각속도가 급증 → `밀착 불균형` 경고 표시, 경로는 유지
- 세 거리값이 동시에 증가하거나 측정범위를 벗어나고 가속도 크기가 급변 → `벽면 이탈 위험`으로 승격, 경로 일시정지 및 모터 출력 차단 래치
- 정지 원인과 직전 센서값을 사건 기록으로 저장하고, 센서값이 정상으로 돌아와도 운용자가 명시적으로 해제하기 전까지 재구동하지 않음
- 해제 후에는 중단된 waypoint부터 경로를 재개

○ 통신 단절 시나리오

- 관제 콘솔·Nano B01 사이 WebSocket이 끊기면 Nano B01은 STM32에 정지 명령을 유지
- Nano B01·STM32 사이 UART가 끊기면 STM32가 자체적으로 300ms 타임아웃을 감지해 PWM을 0으로 차단
- 재연결 시 STM32 재부팅 가능성을 고려해 브릿지를 정지 래치 상태로 다시 초기화하고, 운용자가 해제해야 재구동

#### 2) 적용 알고리즘

○ 아케이드 믹싱 (조종 입력 → 좌·우 궤도 출력)

- 입력 `throttle, turn ∈ [-100, 100]` → `L = throttle + turn`, `R = throttle - turn`
- 좌·우 출력을 `[-100, 100]`으로 클램프하고 부호는 방향 GPIO, 절댓값은 PWM 듀티로 변환
- 방향 반전 시 듀티 0을 약 100ms 경유하는 감속 램프를 삽입해 드라이버 역기전력 충격 완화
- 기동 데드존(무부하 기준 20% 미만 확인)을 하한으로 보정해 저속 명령이 무회전으로 사라지지 않도록 처리

○ 차동 구동 오도메트리 (엔코더 → 로봇 위치)

- 좌·우 이동거리 `s_L, s_R = (Δcount / (CPR × 감속비)) × π × D` (D = 구동륜 유효 지름)
- 전진량 `Δs = (s_L + s_R) / 2`, 회전량 `Δθ = (s_R - s_L) / b` (b = 좌·우 궤도 중심 간격)
- 누적 `x += Δs·cos(θ + Δθ/2)`, `y += Δs·sin(θ + Δθ/2)`, `θ += Δθ`
- 궤도는 회전 시 슬립이 크므로 `Δθ`는 IMU 자이로 적분값으로 단기 보정하고, 보정계수는 실측으로 확정

○ 커버리지 경로 생성

- 원통 사일로 측면을 `가로 = πD, 세로 = 점검 높이`의 2D 전개도로 변환
- 유효 점검폭 `w_eff = w_cam × (1 - 중첩률)`을 이용해 스트라이프 개수 `n = ceil(가로 / w_eff)` 산출
- 세로 지그재그·가로 지그재그 두 후보에 대해 `비용 = 총 이동거리 + k × 회전횟수`를 계산해 낮은 쪽을 추천
- 상·하·좌·우 안전여백을 반영해 경계 waypoint를 안쪽으로 이동

○ 부착 방향 독립 위험 판정 상태머신

- 상태: `정상 → 경고(밀착 불균형) → 위험(벽면 이탈) → 정지 래치`
- 지표: IMU 각속도 크기 `|ω|`, 단시간 자세 변화량 `Δθ/Δt`, 가속도 크기 `|a|`, 3점 거리 평균 `d̄`, 편차 `d_max − d_min`, 변화율 `dd̄/dt`
- 승격 조건: 단일 지표 이상은 경고에 머무르고, **복수 지표 이상이 일정 시간 지속될 때만** 다음 상태로 승격
- 해제 조건: 센서값 정상 복귀만으로는 해제하지 않고, 운용자의 명시적 해제 입력을 요구
- 절대 Roll·Pitch는 상태 판정에 사용하지 않고 현재 부착 방향(바닥·벽·천장) 표시용으로만 사용
- 각 임계값·지속시간은 실물 지그 시험 후 확정하며, 실측 전 성능 수치는 기재하지 않음

○ 결함 탐지 파이프라인

- AI Hub 균열 데이터셋 → YOLO 라벨 변환 → YOLOv8s 파인튜닝(학습 GPU: RTX 4060) → ONNX → TensorRT 엔진
- Orin에서 RTSP 프레임 추론 후 **박스 좌표·클래스·신뢰도만** WebSocket 전송, 영상 재인코딩 없음
- 관제 콘솔이 원본 영상 위에 좌표를 오버레이하고, 탐지 결과를 Orin 로컬 JSONL로 기록

#### 3) 이론적 배경

○ 할바흐 배열의 자속 편향

- 자화 방향을 일정 각도씩 회전시켜 배열하면 한쪽 면에서 자속이 보강되고 반대면에서는 상쇄되어, **같은 자석 질량으로 벽면 방향 자속밀도를 높일 수 있다**
- 로봇 상부로 새는 자속이 줄어 상부 전자장비·배선에 대한 자기 간섭도 함께 감소

○ 자력 부착력과 공극의 관계

- 자기 흡인력은 공극 `g`가 커질수록 급격히 감소하므로, 부착력 조절은 자석을 바꾸지 않고 **`g`를 기구적으로 바꾸는 방식**이 가장 단순하다
- 본 작품의 가변 자력 구조는 자석 1열을 벽면 수직 방향으로 이동시켜 `g`를 바꾸는 방식이며, 이는 2025년 회전식(자화 방향 간섭)보다 공간 효율이 높음
- 곡면에서는 궤도가 곡률을 따라가지 못하면 `g`가 국소적으로 벌어져 부착력이 급감하므로, **곡률 적응형 서스펜션은 부착력 유지 장치이기도 하다**

○ 벽면 부착 로봇의 이탈 조건

- 미끄러짐 조건: 마찰계수 `μ`와 부착력 `F_mag`의 곱이 로봇 자중의 벽면 방향 성분보다 커야 함 (`μ·F_mag > W`)
- 전복(peel) 조건: 자중이 만드는 벽면 이탈 모멘트가 자석 배열의 복원 모멘트보다 작아야 하며, **접지 길이가 길수록 유리**해 휠형 대비 궤도형이 유리
- 위 두 조건 모두 `g`에 민감하므로, 부착력 실측은 자석 위치별 **분리 시작 하중**으로 정량화한다

○ 자세 추정에서 중력 기준의 한계

- 지상 로봇의 자세 추정은 가속도계가 관측하는 중력 방향을 기준으로 Roll·Pitch를 보정하는 상보필터가 일반적이다
- 그러나 벽면·천장 주행에서는 **중력 방향이 로봇 기준으로 계속 바뀌므로 절대 Roll·Pitch가 위험 지표가 되지 못한다**
- 따라서 본 작품은 절대 자세 대신 **각속도·가속도 변화율과 벽면 3점 거리의 공간 편차**를 위험 지표로 사용한다

○ 역할 분리 구조의 근거

- 모터 PWM은 마이크로초 단위의 결정성이 필요해 범용 OS의 스케줄링 지연을 허용하기 어려우므로 **베어메탈 MCU(STM32)** 가 담당
- 로봇 전체 제어·센서 융합·카메라는 **ROS2 노드 분리**로 기능별 독립성과 재시작 내성을 확보
- CNN 추론은 실시간 제어와 자원 경합을 일으키므로 **연산 전용 장치(Orin)** 로 분리하고, 결과는 좌표만 회신해 대역폭을 절약

#### 4) 정량 검증 계획

- 캐리어 저울을 이용해 자석 위치별 분리 시작 하중을 5회 반복 측정하고, 평균·표준편차로 가변 자력 구조의 효과를 정량 검증 `【시험 예정】`
- 오실로스코프로 20kHz PWM 파형과 듀티비를 실측하고, 통신 차단 후 출력 차단까지의 지연을 측정해 300ms 페일세이프 검증 `【시험 예정】`
- 거리센서 3개를 20~150mm 기준점에서 ADC-거리 LUT로 보정하고, 평행판·경사판 조건에서 편차 재현성 확인 `【시험 예정】`

### 5. 기타 사항 — 작품의 가치(Value) 및 제작 노력

○ 차별화된 성능

- 곡률 적응형 서스펜션으로 평면과 곡면을 같은 주행부로 대응해, 대상 형상마다 장비를 바꾸지 않아도 되도록 설계
- 부착력을 자석 교체가 아니라 공극 조절로 바꿔, 부착 안정성과 탈착 편의성을 하나의 구조에서 조절
- 실시간 제어와 CNN 추론을 물리적으로 분리해, 영상 연산 부하가 모터 제어 주기를 침범하지 않도록 구성

○ 신뢰성

- 통신 단절 시 STM32가 자체 타임아웃으로 300ms 이내 모터 출력을 차단하는 제어기 근접 페일세이프
- 일반 정지와 구별되는 별도 비상정지 명령과, 명시적 해제 전까지 유지되는 정지 래치
- 재연결 시 STM32 재부팅 가능성을 고려해 브릿지를 정지 상태로 재초기화하는 안전측 기본값
- 위험 판정은 단일 센서 순간값이 아니라 복수 지표의 일정 시간 지속을 요구해 오탐 정지를 억제
- 실측 전 성능 수치를 보고서에 기재하지 않는다는 원칙을 팀 내부 규칙으로 운영

○ 사용성

- 물리 키보드 없이 7인치 터치만으로 주행·비상정지·주소 설정·기록까지 수행
- RTSP 주소와 WebSocket 포트를 소스 수정 없이 화면에서 변경·영구 저장
- 좌·우 엄지 조작 영역으로 전후진과 조향을 동시에 입력해 장갑 착용 현장 조작을 고려
- 관제 콘솔이 접속을 기다리는 서버 역할을 맡아, 로봇·서버의 전원 순서와 무관하게 자동 연결

○ 보안

- 전 구간을 Tailscale(WireGuard 기반) 오버레이 네트워크로 묶어, 공인 IP 개방이나 포트포워딩 없이 장치 간 암호화 터널로만 통신
- 장치 인증을 네트워크 계층에서 처리해 관제 콘솔·로봇·영상처리 서버 외의 임의 접속을 차단
- 영상·제어 채널을 인터넷에 직접 노출하지 않으며, 폐쇄망 현장에서는 사설 IP 유선 직결로 외부 경로 자체를 제거
- 점검기록은 외부 클라우드로 자동 업로드하지 않고 장치 로컬에 저장해, 시설 내부 영상의 유출 경로를 최소화

○ 알고리즘의 창작성

- 벽·천장 주행에서 중력 기준 절대 자세가 무의미해지는 문제를 인식하고, **부착 방향에 독립적인 복합 위험 판정 상태머신**을 자체 정의
- 정지 조건을 단일 임계값이 아니라 `IMU 동특성 + 3점 거리 공간 편차 + 지속시간`의 결합으로 구성해, 정상적인 벽→천장 전이와 실제 이탈을 구분
- 원통 사일로를 2D 전개도로 환원하고 `이동거리 + 회전 비용`으로 커버리지 경로안을 비교·추천하는 방식으로, 점검 누락 없이 경로 효율을 선택
- 결함 탐지를 영상 합성이 아니라 **좌표 전송 + 관제 측 오버레이**로 설계해 재인코딩 지연과 대역폭을 함께 절감

○ 데이터와 프로그램의 가치

- 점검 결과를 사진 파일 더미가 아니라 **`이미지 + 촬영시각 + 경로상 위치 + waypoint + IMU + 3점 거리 + 안전상태`가 하나의 record id로 묶인 JSONL**로 축적
- 동일 사일로를 반복 점검하면 같은 위치의 시계열 비교가 가능해, 결함 진행 여부 판단과 보수 이력 관리의 근거 데이터가 됨
- 수동 기록과 AI 탐지 결과가 같은 형식을 공유해, AI 완성 전 확보한 기록도 그대로 학습·검증 자료로 재사용 가능
- 장치별 소스코드를 GitHub 조직의 4개 저장소로 분리 관리해, 기능 단위 재사용과 다른 철제 구조물 대상 이식이 가능한 구조

○ 작품을 통한 가치창출

- 작업자 투입 전 원격으로 위험구간을 먼저 확인하는 **선행 점검 단계**를 현장 절차에 추가
- 이상 구간을 선별해 정밀점검·보수 자원을 집중시켜, 전면 정밀검사 대비 점검 자원의 배분 효율 개선
- 점검 영상·탐지 로그를 안전보건 의무 이행 과정의 문서화 자료로 활용

○ 제작 노력과 문제 해결

- 상용 주행 플랫폼을 구매·개조하지 않고, 항만 사일로의 곡면 철제 벽면을 목표로 궤도 프레임·구동륜·궤도·힌지·장력조절부를 직접 CAD 설계하고 3D 출력
- 2025년 궤도 전파손 원인을 공차와 적층 방향으로 분석하고 2026년 구조 재설계
- Jetson Nano OS 제약에 맞춰 ROS2 배포판을 Eloquent로 재선정
- Nano B01에 ADC가 없는 문제를 STM32 ADC 상행 텔레메트리로 해결
- Google Drive의 Git 메타데이터 차단을 발견하고 장치별 코드를 별도 저장소와 GitHub로 이관
- 부품 배송 지연에 대비해 기구 조립과 독립적으로 검증 가능한 항목을 먼저 분리해 벤치에서 선행 검증

○ 기능 확장 방향

- 배터리 전압·전류 측정 회로를 추가해 잔량 표시와 저전압 자동 복귀 구현

- 평면 시험을 통과한 기능만 철판 부착 시험으로, 철판 시험을 통과한 기능만 곡면 시험으로 단계 승격
- AI보다 기구 조립·부착 안정성·안전정지·경로추종을 먼저 완료
- 각 주차의 완료 여부를 사진·영상·로그·실측표로 남기고 미완료 항목은 다음 주로 명시적으로 이월

### 3. 프로젝트 추진 과정에서의 문제점(애로사항) 및 해결방안

#### 1) 프로젝트 관리 측면

○ 코드 저장소와 문서 저장소 혼재

- 문제점: Google Drive가 `.git` 파일을 차단해 로컬 Git 이력 손실 위험과 볼트 용량 증가 발생
- 해결방안: 코드는 로컬 개발 경로와 GitHub 장치별 저장소로 분리하고 볼트는 기록·근거자료 전용으로 운영
- 결과: STM32·RPi4·Nano B01·Orin의 4개 저장소 원격 반영과 작업 경로 통일

○ 제한된 실기 일정과 장비

- 문제점: 기구 조립 전 소프트웨어·통신·구동 검증을 병행해야 하고 학교 네트워크 사용이 어려움
- 해결방안: 실물 없이 가능한 코드를 먼저 개발하고 벤치 단위로 카메라·통신·모터 구간을 분리 검증
- 결과: Nano B01과 RPi4를 유선 직결해 인터넷 없이 RTSP·WebSocket 통합시험 완료

○ 부품 배송 지연에 대한 일정 대응

- 문제점: 일부 조립 부품 도착이 늦어져 기구 조립과 전장 통합 일정이 제출 마감에 근접
- 해결방안: 조립 의존 작업과 비의존 작업을 분리하고, 비의존 작업(펌웨어·통신·영상·센서 벤치·HIL)을 선행 배치
- 결과: 8/24 궤도·프레임 기구 조립을 완료했고, 선행 검증한 제어·영상 기능을 전장 탑재 후 바로 통합할 수 있도록 준비

#### 2) 작품 개발 측면

○ 2025년 궤도 전파손

- 문제점: 궤도 링크 공차와 3D 프린팅 적층 방향을 고려하지 않아 첫 구동 시 궤도 전체 파손
- 해결방안: 하중 방향·출력 특성을 반영해 궤도를 재설계하고 곡률 적응형 서스펜션 구조 적용
- 결과: 2026년 기구 설계 개선과 임베디드 지식 보강의 출발점으로 활용

○ 거리센서 연결 경로 오류

- 문제점: 아날로그 출력 거리센서를 ADC가 없는 Nano B01에 직접 연결하도록 초기 설계
- 해결방안: STM32 ADC 3채널에서 값을 읽고 UART 상행 텔레메트리로 Nano B01에 전달
- 결과: 추가 ADC 모듈 구매 없이 기존 제어기를 활용한 센서 데이터 경로 확보

○ ROS2 버전·운영체제 호환성

- 문제점: Jetson Nano B01의 Ubuntu 18.04에서 ROS2 Humble·Foxy 공식 바이너리 사용 불가
- 해결방안: Ubuntu 18.04 arm64 공식 지원 배포판인 ROS2 Eloquent로 변경
- 결과: 기존 JetPack·CSI 카메라 환경을 유지하며 ROS2 노드 빌드·실행 성공

○ 비상정지 래치 상태 불일치

- 문제점: STM32는 부팅 직후 정지 래치 상태지만 Nano 브릿지는 해제 상태로 시작해 정지 해제 명령 미전송
- 해결방안: 브릿지 초기값과 시리얼 재연결 상태를 정지 래치로 변경하고 명시적 해제 후 제어
- 결과: RPi4→Nano B01→STM32→모터 4개 전체 제어 경로 정상 동작 확인

○ 인터넷 없는 실기 환경

- 문제점: Nano B01 무선랜카드 미도착과 학교 네트워크 제한으로 Tailscale 연결 불가
- 해결방안: Nano B01과 RPi4를 랜선으로 직결하고 양쪽에 고정 IP 설정
- 결과: RTSP 실시간 영상과 WebSocket 제어·상태 채널의 엔드투엔드 통신 확인

○ 벽면 주행에서의 자세 판정 기준 부재

- 문제점: 일반 지상 로봇의 절대 Roll·Pitch 임계값 방식을 적용하면 정상적인 벽→천장 전이를 위험으로 오판
- 해결방안: 절대 자세를 표시용으로만 사용하고, IMU 각속도·변화량과 3점 거리 편차·변화율의 복합 조건으로 위험을 판정하는 상태머신으로 재설계
- 결과: 부착 방향에 독립적인 안전 판정 로직을 정의하고, 외란 모사 시험 항목을 구체화

### 4. 프로젝트를 통해 배우거나 느낀 점

○ 멘토링 프로그램 참여를 통해

- 산업 현장 경험을 가진 멘토의 검토를 통해, 학생 과제의 기술 목표와 실제 현장 요구가 어디서 갈라지는지 확인할 수 있었음
- 월 1회 이상의 정기 멘토링이 설계 방향을 되돌릴 수 있는 시점에 점검하는 역할을 해, 2025년과 달리 큰 재작업 없이 진행할 수 있었음
- 2025년 같은 프로그램에서 겪은 실패를 다음 해 같은 프로그램에서 개선해 제출할 수 있었던 점이, 연속 참여형 프로그램의 가장 큰 이점이라고 느낌
- 해운물류라는 구체적인 산업 영역이 주어짐으로써, 막연한 벽등반 로봇이 아니라 `항만 사일로 안전점검`이라는 좁고 명확한 문제로 과제를 좁힐 수 있었음

○ 기술적으로 배운 점

- 기구 공차·적층 방향·배선 극성과 같은 물리적 조건이 소프트웨어 동작만큼 중요함을 확인
- 장치별 기능 완성보다 UART·WebSocket·RTSP 인터페이스 계약과 통합시험이 전체 완성도를 좌우함을 경험
- 비상정지·통신 타임아웃·재연결 초기화 등 실패 상태를 먼저 설계하는 안전 제어의 중요성 학습
- 운영체제·ROS2·JetPack 호환성을 확인한 뒤 기술을 선정해야 재작업을 줄일 수 있음을 체득
- 일반적인 지상 로봇의 가정(중력 기준 자세)이 벽면 로봇에서는 성립하지 않음을 확인하고, 문제 조건에 맞는 판정 기준을 새로 정의하는 경험

○ 협업에서 배운 점

- 실패 원인과 버린 대안까지 기록하면 팀원 간 판단 공유와 보고서 작성의 근거로 재사용할 수 있음을 확인
- 기계·전기·소프트웨어·영상처리 담당 간 협업을 통해 단일 전공만으로 해결하기 어려운 통합 문제 해결
- 부품 배송처럼 팀이 통제할 수 없는 변수는 일정에서 분리해, 통제 가능한 작업을 먼저 배치하는 것이 실질적인 위험관리임을 경험

- 밀폐공간 또는 고소 철제 구조물의 안전점검·유지보수 담당자
- 점검 작업자의 위험 노출과 설비 가동 중단을 줄여야 하는 안전·시설 관리 책임자

○ 적용 분야

- 항만 곡물·사료 사일로 내·외부 벽면 점검
- 석유화학·산업용 철제 저장 탱크 표면 점검
- 강재 교량·선박·해양플랜트 등 자력이 작용하는 철제 구조물 점검
- 사람이 직접 접근하기 어려운 밀폐공간·고소 벽면의 영상 모니터링

### 2. 작품의 활용에 의한 기대효과(사용자)

○ 작업자

- 밀폐공간 진입과 고소 벽면 직접 접근을 줄여 질식·추락·유해물질 노출 위험 저감
- 사람이 접근하기 어려운 구간을 원격 영상으로 먼저 확인해 작업 전 위험요인 파악

○ 시설 운영자

- 비계·로프·안전장비 설치 전 로봇을 이용한 선행 점검 가능
- 실시간 영상과 결함 위치 기록을 통해 보수 우선순위 판단 지원
- 반복 점검 결과를 데이터로 남겨 시설 상태 변화와 유지보수 이력 관리

○ 안전관리 책임자

- 작업자 투입 전에 현장 상태를 확인할 수 있는 추가적인 판단 근거 확보
- 안전보건 의무 이행 과정의 점검 영상·탐지 로그 등 문서화 자료 확보
- 법정 가스측정·환기·보호구·감시인 등 안전조치를 대체하지 않고, 원격 영상·상태 정보로 작업자 투입 판단을 보조[^3]

### 3. 작품의 기대가치

○ 기존 서비스와의 차별성

- 비계·로프 기반 인력 점검 대비: 작업자 투입 전 원격 선행 확인이 가능하고, 준비 작업 없이 반복 점검 가능
- 드론 점검 대비: 벽면에 부착한 상태로 근접 거리를 유지해 미세 표면 이상 촬영에 유리하고, 밀폐공간 통신·기류 영향이 작음
- 상용 자력 NDT 크롤러 대비: 초음파 정밀검사를 대체하는 것이 아니라, **정밀검사 대상 구간을 선별하는 선행 점검 단계**로 위치를 구분
- 공통 차별성: 영상·자세·거리·안전상태를 하나의 점검기록으로 묶어 사후 재확인과 시계열 비교가 가능

○ 시장성 (가격 우위성)

- 본 작품은 상용 완제품이 아니라 **범용 부품과 자체 설계·3D 출력 기구부의 조합**으로 구성되어, 장치 원가가 부품비 수준에서 형성됨
- 2026년 실제 집행 기준 총 재료·장비비는 약 231만원이며, 이 중 상당 부분이 개발용 장비(영상처리 서버·개발 키트)로 양산형 구성에서는 제외 가능
- 기구부는 3D 프린팅과 알루미늄 프로파일로 구성되어 **형상 변경 비용이 금형 기반 제품보다 현저히 낮고**, 대상 구조물별 맞춤 제작이 가능
- 상용 자력 NDT 크롤러는 공개 가격이 공시되지 않아 직접적인 가격 비교는 제시하지 않으며, 본 작품의 가격 우위는 **부품 조달 가능성·자체 제작 가능성·형상 변경 비용** 세 축으로 제시
- 실제 판매가격·비용 절감률·시장규모는 현장 실증과 수요조사 전까지 단정하지 않음

○ 사회적 가치

- 밀폐공간·고소작업 등 고위험 점검 업무에서 작업자의 직접 노출을 줄이는 산업안전 수단
- 사람이 접근하기 어려운 시설 구간까지 점검 범위를 확대해 예방적 유지보수 지원
- 질식재해 사망률이 높은 밀폐공간 작업에서 `사람이 들어가기 전에 로봇이 먼저 본다`는 절차를 현장에 제안

○ 경제적 가치

- 비계 설치와 작업자 직접 접근이 필요한 점검 전 로봇을 활용한 선행 확인 가능
- 결함 의심 구간을 우선 선별해 정밀점검·보수 자원의 집중 지원
- 설비 가동 중단 시간을 줄이기 위한 점검 계획 수립 근거로 활용

○ 확장 가치

- 항만 사일로에서 검증한 자력 부착·원격 관제·결함탐지 기술을 다른 철제 구조물로 확대 가능
- 축적된 점검기록이 늘어날수록 결함 탐지 모델의 재학습 자료로 활용 가능
- 향후 센서·점검 도구 확장 가능성은 있으나, 현재 보고서에서는 모듈 교체가 구현된 것으로 표현하지 않음
