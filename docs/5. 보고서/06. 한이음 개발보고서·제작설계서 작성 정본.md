## 1. 이번 공모전에서 잡을 한 문장

> 사일로봇은 작업자가 접근하기 위험한 철제 구조물 표면을 직접 주행하며, 근접 영상과 주행 상태를 원격으로 전달하고 이상 상황에서 구동을 차단하는 곡면 적응형 궤도 점검 플랫폼이다.

한이음에서는 항만 서사만 길게 쓰지 않는다. 다음 네 가지를 일관되게 증명한다.

1. **직접 설계한 이동 플랫폼** — 구동륜·궤도·프레임·장력 구조를 구매 완제품이 아니라 직접 설계·제작
2. **곡면 적응 구조와 자력 부착 개념** — 스프링 쇼바형 궤도로 접촉 유지, 자력 간섭 구조로 부착력 조절 가능성을 탐색
3. **분산 제어와 원격 관제** — RPi4 터치 콘솔 → Jetson Nano → STM32 → 4개 모터, CSI 영상의 RTSP 실시간 송출
4. **안전 중심 설계** — 비상정지 래치, 통신 이상 정지, IMU·3점 거리센서를 결합한 이격 위험 감시 구조

AI 결함탐지는 실제 학습·실시간 추론 지표가 확보되기 전까지 `파이프라인 구현 중`으로 표기한다. 반자율 주행은 경로 생성·추종 코드와 오프로봇 시험을 설명하되, 실물 경로 완주 전에는 `실물 자율주행 완료`로 쓰지 않는다.

### I. 프로젝트 개요 — 2장 이내, 개조식

#### 1. 프로젝트 소개

- 철제 구조물 표면에 부착해 이동하는 곡면 적응형 궤도 점검 로봇
- 근접 카메라 영상, 원격 주행 제어, 주행 상태 감시, 위험 시 정지를 하나의 시스템으로 통합
- 구동륜·궤도·프레임 등 핵심 기구부를 직접 설계·제작

권장 그림: 작품 전체 구성도 또는 CAD 조립도 1장.

#### 2. 개발 배경 및 필요성

- 탱크·사일로 등 밀폐·고소 철제 구조물은 작업자 접근 자체가 위험하고 육안 점검의 누락 가능성이 존재
- 드론은 비접촉 원거리 관측에 유리하지만 철제 표면에 밀착한 연속 근접 촬영과 안정적인 동일 거리 유지에는 제약
- 기존 상용 벽면 로봇은 특정 구조물·점검 장비에 최적화돼 학생 팀이 확보·개조하기 어렵고 비용 부담이 큼
- 따라서 저비용 직접 제작 플랫폼으로 작업자 투입 이전의 1차 근접 점검과 기록을 지원하는 것을 목표로 설정

권장 그림: `작업자 투입 위험 → 로봇 근접 점검 → 관제·기록` 3단 흐름도.

#### 3. 프로젝트 특·장점

- 평면 주행 로봇이 아닌 **철제 곡면 접촉을 고려한 직접 설계 궤도**
- 단순 무선 조종을 넘어 **모터 실시간 제어·영상·상태 감시·안전정지**를 계층적으로 통합
- 영구자석 기반 구조로 진공 흡착용 펌프 없이 부착 가능성을 확보하고, 간섭 자석 이동에 따른 부착력 변화 가능성을 실험 대상으로 설정
- 2025년 고정 궤도형 청소 로봇에서 2026년 곡면 적응형 점검 플랫폼으로 개선
- 향후 센서·점검 모듈을 교체할 수 있는 플랫폼 방향성을 제시하되, 실제 탈부착 모듈은 미구현임을 명시

권장 그림: `2025 고정 궤도/청소 → 2026 곡면 적응 궤도/점검·안전` 비교표.

- H/W: NUCLEO-F401RE, Jetson Nano B01, Raspberry Pi 4, 7인치 터치스크린, CSI 카메라, IMU, 거리센서 3개, 엔코더 모터 4개, 모터 드라이버 2개
- 통신: UART, WebSocket, RTSP, Wi-Fi/Tailscale
- 관리: GitHub 형상관리, 회의·역할분담·이슈 공유 방식은 실제 팀 운영 사실 확인 후 기재

#### 5. 기타 사항

- 핵심 기구를 직접 설계하고 3D 프린팅한 제작 노력
- 제어 계층을 분리해 장애가 상위 장치에 생겨도 STM32가 정지하도록 한 안전 설계
- 실제 로봇이 완성되지 않은 단계에서도 모터·통신·영상·안전 기능을 각각 검증할 수 있게 벤치 시험 환경 구성
- 시험으로 확보하지 않은 수치와 성능은 넣지 않음

### III. 프로젝트 수행 내용

#### 1. 프로젝트 수행일정

- 4~5월: 요구사항·기존 구조 분석
- 5~6월: 궤도·구동륜·프레임 CAD 설계, 부품 선정

- 7~8월: STM32 모터 제어, Nano 연동, RPi4 관제, RTSP 영상, 안전정지 구현
- 8~9월: 센서 통합, 실측 보정, 통합 시연, AI 학습·추론 연동
- 9~10월: 반복 검증, 문서화, 성과 등록

#### 2. 프로젝트 추진 과정에서의 문제점 및 해결방안

관리 측면 후보:

- 부품 도착 지연 → 기구·전장·소프트웨어를 분리해 벤치 검증을 선행
- 여러 장치 동시 개발 → 통신 규격·노드·토픽을 문서로 고정하고 장치별 저장소로 관리

개발 측면 후보:

- 비상정지 해제 뒤 재구동 불가 → 정지 래치와 해제 상태전이를 수정하고 반복 시험으로 정상 복귀 확인
- 엔코더 방향·조향 부호 불일치 → 좌우 카운트와 회전 방향을 분리 시험하고 역검증 테스트 추가
- Nano의 영상처리 성능 한계 → 로봇 제어는 Nano, AI 추론은 Orin으로 역할 분리
- 부품 지연으로 완성체 시험 불가 → 프로파일 장착 모터·센서로 외란과 정지 기능을 먼저 모사

#### 3. 프로젝트를 통해 배우거나 느낀 점

- 기구·전장·통신·UI가 동시에 맞아야 로봇 기능이 성립한다는 점
- 안전 기능은 화면 표시가 아니라 최하위 제어기에서 실제 출력을 끊어야 한다는 점
- 구현 여부와 실물 검증 여부를 분리해 기록해야 재현성과 신뢰성을 확보할 수 있다는 점
- 일정 지연 시 완성체만 기다리지 않고 하위 기능별 시험 증거를 축적하는 방식의 중요성

### IV. 기대효과 및 활용분야

#### 1. 기대효과

- 밀폐·고소 철제 구조물에 작업자가 직접 진입하기 전 원격 1차 점검 지원
- 근접 영상을 반복 가능한 경로에서 수집해 점검 기록의 연속성과 추적성 향상
- 직접 제작 플랫폼으로 교육·연구·현장 맞춤형 센서 실험 비용 절감

#### 2. 활용분야

- 항만 탱크·사일로 외벽 및 내부 철제면
- 선박 외판·대형 저장탱크·철제 교량·플랜트 구조물
- 도장 상태, 균열, 부식 등 표면 결함의 근접 촬영과 이력 관리

## 4. 응용하드웨어 제작설계서 권장 구성

공식 템플릿은 36장짜리 예시 모음이다. 모든 예시를 채우는 방식이 아니라 2쪽의 `응용 하드웨어` 필수 산출물을 빠짐없이 남기고, 사일로봇 증거에 맞춰 선택 슬라이드를 구성한다.

### 제출 본편 — 16~20장 권장

1. 표지 — 프로젝트명, 날짜, 팀명만
2. 시장·기술 동향 — 사람 투입 점검, 드론, 상용 벽면 로봇의 장단점
3. 요구사항 정의서 — 부착·주행·영상·정지·센서·기록 요구사항
4. 시스템 구성도 — RPi4/Nano/STM32/Orin/모터·센서 연결
5. 서비스 시나리오 — 부착·연결·주행·점검·위험감지·기록
6. 하드웨어·센서 구성도 — 핀/인터페이스/전원/통신 표
7. 관제 메뉴 구성도 — 수동운전·영상·센서·경로·기록·비상정지
8. 기능 흐름도 — 조작 명령부터 모터 출력과 텔레메트리 반환까지
9. 안전 알고리즘 명세 — E-stop·통신 타임아웃·IMU/거리 위험 상태
10. 반자율 알고리즘 명세 — 영역 입력·왕복 경로·추종·중지 조건
11. 기구 설계도 — CAD 전체 조립도와 궤도 단면
12. 곡면 적응 궤도 상세 — 쇼바·힌지·장력 구조와 설계 의도
13. 자력 구조 상세 — 자석 배치와 가변 원리, 정량 시험은 미검증 표기
14. 프로그램 목록 — 장치별 모듈·노드·서비스 목록
15. 핵심 소스코드 1 — STM32 안전정지·통신 타임아웃
16. 핵심 소스코드 2 — Nano 명령 중재·센서 안전감시 또는 RPi4 제어
17. 개발 환경 — S/W·H/W·통신·형상관리 표
18. S/W 기능 실사 — 관제 화면·실시간 영상·정지 상태
19. H/W 기능 실사 — 직접 설계 부품·기구 조립·모터 구동
20. 프로젝트 관리·검증 — Git 이력·시험 로그·문제 해결 기록

선택 슬라이드인 설문조사·인터뷰·ERD·테이블 정의서는 실제 자료가 없으면 억지로 만들지 않는다. 화면 설계서는 대시보드 화면과 기능 정의를 보여주는 1장만 추가할 수 있다. 템플릿의 샘플 문구와 붉은 안내문은 최종본에서 모두 제거한다.
