## 1. 원본 예시에서 파악한 작성 방식

### 공통 레이아웃

- 모든 본문 페이지는 왼쪽 위 파란 제목 영역, 오른쪽 위 한이음 로고, 흰색 본문 배경을 유지한다.
- `샘플 1`, `샘플 2`와 하단의 빨간 안내문은 최종본에서 전부 삭제한다.
- 예시처럼 한 페이지에 한 종류의 산출물만 둔다. 서로 다른 표·도식·사진을 무리하게 섞지 않는다.
- 표와 도식은 화면을 채울 정도로 크게 배치하고, 설명은 그림을 해석하는 데 필요한 수준으로 제한한다.
- 학교명, 팀원 실명, 소속은 표지와 본문·사진 캡션·코드 경로에서 모두 제거한다.

### 산출물별 예시의 의미

| 원본 예시 | 예시가 보여주는 작성 형식 | 사일로봇 적용 원칙 |
|---|---|---|

## 4. 최종 20쪽 상세 작성계획

### 1쪽. 응용하드웨어 제작설계서

- **사용 예시:** 원본 1쪽
- **예시에서 가져올 형식:** 큰 문서 제목, 프로젝트명 한 줄, 작성일과 팀명만 둔 최소 표지
- **제목:** `응용하드웨어 제작설계서`
- **프로젝트명:** `가변 자력 기반의 곡면 적응형 궤도를 활용한 철제 구조물 안전 점검 로봇`
- **하단:** `2026. 09. 07`과 `팀명: 사일로봇`
- **최종 확인:** 사이트 등록 프로젝트명과 날짜. `26_HC128`은 확인 전까지 넣지 않는다.
- **금지:** 학교명, 팀원 실명, 학과, 지도교수·멘토 이름

### 2쪽. 개발 배경과 기술 동향

- **사용 예시:** 원본 3쪽
- **예시에서 파악한 형식:** 상단에 근거 그림 2개, 하단에 이를 해석하는 짧은 문단
- **페이지 목적:** 위험 철제 구조물에 원격 점검 로봇이 필요한 이유를 공식 근거로 제시
- **왼쪽 그림:** 탱크·사일로 내부의 밀폐공간 위험요인 표
  - 산소결핍·유해가스
  - 추락·협소공간
  - 작업 전 상태 확인의 어려움
- **오른쪽 그림:** 공식 통계 `2013~2022년 재해자 362명, 사망자 154명`
- **하단 문안 방향:** 사람이 먼저 진입하기 전에 영상과 상태를 확인하는 보조수단이 필요하다고
  연결한다. 법정 가스측정·환기·보호구를 대체한다고 쓰지 않는다.
- **근거:** [[5. 보고서/04. 종합조사 사실검증 및 보고서 보조근거]]
- **출처 표기:** 고용노동부 보도자료, 확인 기간과 대상을 함께 표기
- **금지:** 근거 없는 시장규모·CAGR, 비용절감액, 법규 준수 보장

### 3쪽. 기존 점검 방식과 사일로봇

- **사용 예시:** 원본 4쪽
- **예시에서 파악한 형식:** 왼쪽 비교 매트릭스, 오른쪽 기존 방식과 제안 시스템의 상세 비교
- **페이지 목적:** 사일로봇의 위치와 차별점을 과장 없이 설명
- **왼쪽 표 행:** 작업자 직접 접근, 드론, 상용 자력 크롤러, 사일로봇
- **왼쪽 표 열:** 철제면 부착, 근접 연속촬영, 곡면 접촉 대응, 원격 영상, 자체 제작 가능성
- **오른쪽 비교축:** 접근 방식, 점검거리, 이동 구조, 관제 방식, 개발 범위
- **사일로봇 강조:** 직접 설계한 궤도·프레임, 곡면 적응 구조, 분산 제어, 휴대형 관제 콘솔
- **경계:** 상용 장비보다 성능·가격이 우수하다고 단정하지 않는다. 드론 대비 정량 우위도 쓰지 않는다.
- **근거:** JIREH TERAX, Eddyfi VersaTrax, Nexxis SAIR의 공식 제품 설명과 볼트 사실검증 문서

### 4쪽. 시스템 요구사항 정의서

- **사용 예시:** 원본 7쪽
- **예시에서 파악한 형식:** `요구사항 ID / 요구사항명 / 기능 ID / 기능명 / 세부사항 / 예외사항`
  계층표
- **페이지 목적:** 구현 대상을 기능 단위로 고정하고 검증 상태를 함께 보여준다.
- **요구사항 묶음:**
  - `REQ-MOV`: 수동 주행과 좌·우 차동 구동
  - `REQ-VIS`: CSI 영상의 실시간 관제
  - `REQ-SAF`: 비상정지, 통신 단절 정지, 안전 래치
  - `REQ-SNS`: IMU·3점 거리·엔코더·배터리 상태 수집
  - `REQ-AUTO`: 영역 입력, 왕복 경로 생성, 경로 추종
  - `REQ-LOG`: 영상·시각·경로·센서 상태의 점검기록

- **세부사항:** 값 범위, 주기, 프로토콜, 완료조건을 한 문장으로 적는다.
- **예외사항 대신 상태 병기:** `실물 검증 완료 / 코드·오프로봇 검증 / 실물 통합 대기 / 미완성`

- **경계:** `REQ-AI`는 파이프라인 구현 중, `REQ-AUTO`는 실물 경로 완주 미검증으로 표시

- **정확한 표현:** STM32는 RTOS가 아니라 베어메탈
- **경계:** Orin 학습·TensorRT 엔진이 완료된 것처럼 표시하지 않는다.

## 7. PPTX 작성 순서

1. 원본 PPTX 사본을 만들고 사용할 20쪽 레이아웃만 남긴다.
2. 모든 샘플 이미지·샘플 문구·빨간 안내문을 제거한다.
3. 필수 9종 산출물 페이지부터 표·도식·코드 내용을 채운다.
4. 볼트의 구성도와 기존 캡처를 배치하고 부족한 사진 자리를 확정한다.
5. 실제 코드 HEAD에서 핵심 함수와 커밋을 다시 확인해 코드 페이지를 작성한다.
6. 실사 사진을 교체하고 각 사진에 현재 검증 상태를 붙인다.
7. 개인정보·학교명·실명·개인 경로를 전수 검사한다.
8. PDF 1-up으로 변환한 뒤 20쪽 전체의 글자 잘림, 표 가독성, 샘플 잔존 여부를 검수한다.
