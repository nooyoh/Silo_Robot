# 장치별 동작 및 명령어

전원 인가, 업데이트, 실행, 정지, 로그 확인에 사용하는 **복붙용 운용 정본**이다. 핀 배선은
[[2. 하드웨어/05. 배선도]], 촬영용 최소 결선은 [[11. 시연용 최소 배선도]]를 따른다.

## 1. 전체 동작

```text
RPi4 대시보드(WebSocket 서버·RTSP 화면)
  │ 조작/경로 명령                     ▲ 상태/센서/위치
  ▼                                    │
Jetson Nano B01(로봇 두뇌·ROS2·RTSP 서버)
  │ 6바이트 모터 명령                  ▲ 거리/엔코더/배터리 프레임
  ▼                                    │
STM32(20 Hz 제어·300 ms 타임아웃) ──→ 모터 드라이버 2개 ──→ 모터 4개

Nano RTSP ──→ Orin Nano(균열 추론) ──WebSocket 탐지결과──→ RPi4
```

- **STM32**: 명령을 PWM·방향으로 바꾸고 엔코더/ADC를 읽는다. 부팅 시 정지 래치이며 명령이
  300 ms 끊기면 자체 정지한다.
- **Nano B01**: STM32·IMU·카메라를 ROS2로 묶고 경로 생성·추종·안전상태·대시보드 통신을 담당한다.
- **RPi4**: WebSocket 서버이자 조작 콘솔이다. 정지/해제, 수동 조작, 경로 시작, 영상·기록 표시를 한다.
- **Orin Nano**: Nano RTSP를 받아 AI 추론만 하고 탐지 박스를 RPi4로 보낸다. 로봇 구동에는 없어도 된다.

현재 기본 주소:

| 항목 | 값 |
|---|---|
| Nano RTSP | `rtsp://100.121.144.38:8554/robot` |
| RPi WebSocket | `ws://100.74.141.112:8765` |
| Nano ↔ STM32 | `/dev/ttyACM0`, 115200 bps |
| Nano ↔ IMU | `/dev/ttyTHS1`, 9600 bps |

주소가 바뀌면 Tailscale 화면의 실제 IP를 우선하고 설정 파일/대시보드 연결 설정도 함께 바꾼다.

## 2. STM32 NUCLEO-F401RE/F411RE

STM32에는 셸 명령이 없다. 펌웨어를 플래시하면 전원 인가 즉시 실행된다.

### 빌드와 플래시 — Windows 개발 PC

```powershell
cd D:\SiloRobot\stm32-controller
$env:PATH="<CubeIDE ARM GCC bin>;<CubeIDE make bin>;$env:PATH"
make BUILD_DIR=C:/Users/<user>/AppData/Local/Temp/silorobot-f401-build
STM32_Programmer_CLI.exe -c port=SWD -w C:/Users/<user>/AppData/Local/Temp/silorobot-f401-build/silorobot-f401re.bin 0x08000000 -v -rst
```

- F411RE를 사용할 때만 빌드 명령에 `DEVICE=f411`을 붙이고 출력 파일도 `silorobot-f411re.bin`을
  사용한다. 보드 실크를 보고 F401RE/F411RE를 확정한 뒤 플래시한다.
- 배터리 분압 2채널을 모두 배선하고 멀티미터로 확인한 뒤에만 `BATTERY_MONITOR=1`을 붙인다.
- 정상 부팅 상태는 **모터 정지**다. Nano에서 해제 명령을 보내야 움직인다.

### PC 단위시험

```powershell
gcc -std=c11 -Wall -Wextra -Werror -DSILO_BATTERY_MONITOR_ENABLED=1 -IApp/Inc App/Src/*.c tests/test_main.c -o tests/test_main.exe
.\tests\test_main.exe
```

## 3. Jetson Nano B01 — 로봇 본체

### 코드 업데이트와 빌드

```bash
cd ~/jetson-nano-b01
git pull
bash scripts/silorobot.sh build
bash scripts/silorobot.sh preflight
```

### 일반 부팅 서비스

```bash
sudo systemctl restart silorobot-nano.service
systemctl --no-pager --full status silorobot-nano.service
journalctl -u silorobot-nano.service -f
```

최초 1회 설치:

```bash
cd ~/jetson-nano-b01
sudo install -m 644 systemd/silorobot-nano.service /etc/systemd/system/silorobot-nano.service
sudo systemctl daemon-reload
sudo systemctl enable --now silorobot-nano.service
```

### 포트·토픽 확인

```bash
ls -l /dev/ttyACM0 /dev/ttyTHS1
groups
bash scripts/silorobot.sh preflight
source /opt/ros/eloquent/setup.bash
source ~/jetson-nano-b01/install/setup.bash
ros2 topic echo /silorobot/stm32_connected
ros2 topic echo /silorobot/safety_state
ros2 topic echo /silorobot/wheel_counts
ros2 topic echo /silorobot/imu_health
```

`tty` 권한이 없으면 `sudo usermod -aG dialout jetson` 후 재로그인한다. IMU GPIO UART는
`sudo systemctl disable --now nvgetty` 후 재부팅해야 한다.

### 시연 전용 — 거리센서·IMU 안전 판단 없이 구동

```bash
cd ~/jetson-nano-b01
sudo systemctl stop silorobot-nano.service
bash scripts/silorobot.sh demo-drive
```

터미널에 `DEMO`를 직접 입력해야 시작한다. 이후 RPi 화면에서 `해제 요청`을 누르고 수동 조작하거나
작은 경로를 생성해 시작한다. 기존 명령 `bench-autonomy`도 남아 있으며 이 경우 `BENCH`를 입력한다.

시연 종료 후 반드시 일반 부팅으로 복귀한다.

```bash
# demo-drive 터미널에서 Ctrl+C
sudo systemctl start silorobot-nano.service
```

| 시연 모드에서 우회 | 계속 동작하는 보호 |
|---|---|
| 거리센서 필수·보정 게이트 | RPi 비상정지 버튼과 STM32 정지 래치 |
| 거리 편차·이탈 자동정지 | Nano 명령 중단 시 STM32 300 ms 타임아웃 |
| IMU 각속도·가속도 자동정지 | 배터리 감시가 실제 배선·활성화된 경우 저전압 정지 |
| `armed=true` 자율주행 게이트 | 시작 전 운영자 `DEMO` 확인과 명시적 해제 |

> [!danger] 시연 모드는 벽면 운용 모드가 아니다
> 궤도를 띄운 상태 또는 장애물이 없는 평평한 바닥에서만 사용한다. 배터리 감시 회로가 미배선이면
> 저전압 보호도 동작하지 않으므로 충전 상태를 별도로 확인한다. 수동 비상정지와 모터 전원 스위치에
> 한 사람이 계속 손을 댈 수 있어야 한다.

### 촬영 비상용 — 0.5 × 0.5m 계획 화면 연동, 10초 사각 주행

RPi의 기존 계획 실행 화면에 0.5 × 0.5m 사각 경로를 표시하고, 현재 위치 마커·방향·웨이포인트·
진행률을 실물 모터 명령과 같은 10초 타임라인으로 움직이는 촬영용 모드다. 경로 생성기와 추종기는
충돌 방지를 위해 실행하지 않고 모터는 시간 기반으로 제어한다.

```bash
cd ~/jetson-nano-b01
git pull
bash scripts/silorobot.sh build
sudo systemctl stop silorobot-nano.service
bash scripts/silorobot.sh demo-square
```

RPi에서 `반자율 전면점검` 팝업을 먼저 열고 터미널에 `SQUARE`를 입력한다. 계획은 즉시 화면에
표시되고 해제 완료 5초 뒤 주행·마커 애니메이션이 자동 시작한다. 화면의 시작 버튼은 누르지 않는다.
기본 실행시간은 `직진 1.5초 ×4 + 회전 0.6초 ×4 + 정지 0.2초 ×8 = 10초`다.

```bash
SQUARE_SIZE_M=0.5 SQUARE_SIDE_SECONDS=1.5 SQUARE_TURN_SECONDS=0.6 \
bash scripts/silorobot.sh demo-square
```

- 실행 중 조이스틱은 건드리지 않는다. 중단은 RPi 비상정지 또는 Nano 터미널 `Ctrl+C`만 사용한다.
- 센서 판단·오도메트리·계획은 우회하지만 RPi 비상정지와 STM32 300ms 명령 타임아웃은 유지된다.
- 최소 1.5 × 1.5m의 평평하고 빈 공간에서 저속으로만 사용하며 벽면에서는 절대 실행하지 않는다.
- 화면의 0.5m 좌표는 촬영 타임라인이다. 엔코더 실측 거리가 아니므로 `0.5m 정밀주행`이나
  `자율 경로 추종 완료`의 근거로 쓰지 않는다.

### 보정 명령

```bash
source /opt/ros/eloquent/setup.bash
source ~/jetson-nano-b01/install/setup.bash
bash scripts/silorobot.sh distance 5
bash scripts/silorobot.sh straight 1.0 20
bash scripts/silorobot.sh turn 6.283185307 <left_m_per_count> <right_m_per_count> 20
ros2 run silorobot_nano verify_signs
```

### 로봇 없이 통합 검증

```bash
python3 tools/verify/run.py
```

## 4. Raspberry Pi 4 — 관제 대시보드

### 업데이트·빌드·자동실행

```bash
cd ~/rpi4-dashboard
git pull
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
bash scripts/install-autostart.sh
```

### 서비스 상태와 로그

```bash
systemctl --user --no-pager --full status silorobot-dashboard.service
journalctl --user -u silorobot-dashboard.service -f
systemctl --user restart silorobot-dashboard.service
```

### 직접 실행

```bash
systemctl --user stop silorobot-dashboard.service
./build/silorobot-dashboard --rtsp rtsp://100.121.144.38:8554/robot
```

UI만 확인할 때의 `--demo`는 가짜 상태 화면용이며 실제 로봇 시연 모드와 다르다.

```bash
./build/silorobot-dashboard --demo
```

RPi가 WebSocket **서버**다. Nano와 Orin이 RPi의 `8765` 포트로 접속한다.

```bash
ss -ltnp | grep 8765
tailscale status
```

## 5. Jetson Orin Nano Super — AI 탐지 서버

Orin은 없어도 카메라 영상·수동/자율 구동·기록은 동작한다. 균열 탐지가 필요할 때만 켠다.

### 최초 환경 구성과 수동 실행

```bash
cd ~/jetson-orin-nano
git pull
bash scripts/setup-runtime.sh
source .venv/bin/activate
python -m inference.main --model artifacts/crack-yolov8s.engine
```

모델·RTSP 없이 통신만 확인:

```bash
source .venv/bin/activate
python -m inference.main --dry-run
```

### 자동실행과 로그

```bash
bash scripts/install-autostart.sh
systemctl --user --no-pager --full status silorobot-orin.service
journalctl --user -u silorobot-orin.service -f
systemctl --user restart silorobot-orin.service
```

주소는 `~/.config/silorobot/orin.env`에서 바꾼다. TensorRT 엔진이 없으면 자동실행 설치가
의도적으로 거부된다.

## 6. 촬영 당일 권장 순서

1. 모터 전원 OFF, 궤도 공중 또는 넓은 평면 확보
2. RPi 켜기 → 대시보드 서비스와 `8765` 확인
3. Nano 켜기 → STM32 USB 연결 → `preflight` 확인
4. 일반 Nano 서비스를 멈추고 `demo-drive` 실행 → `DEMO` 입력
5. 화면이 `STOPPED`이고 영상이 나오는지 확인한 뒤 모터 전원 ON
6. `해제 요청` → 작은 수동 입력으로 네 모터 방향 확인
7. 수동 주행 촬영 후 필요하면 0.5 × 0.5 m 짧은 경로만 촬영
8. 화면 정지 → 모터 전원 OFF → `Ctrl+C` → 일반 서비스 복구

이상이 생기면 튜닝부터 하지 말고 먼저 **대시보드 정지 → 모터 전원 OFF** 순서로 중단한다.
