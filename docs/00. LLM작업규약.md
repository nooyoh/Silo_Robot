## 1. 이 볼트의 목적

진행 관리 도구가 **아니다**. 아카이브다.

1. **기록** — 실제로 있었던 일을 시점과 함께
2. **자소서/포트폴리오 소스** — "문제 → 판단 → 행동 → 결과" 서사로 뽑아 쓸 원재료
3. **LLM 기준점** — 매 대화마다 프로젝트를 처음부터 설명하지 않기 위한 확정 사실 한 벌

세 목적 모두 **"왜 그렇게 했는지"**를 요구한다. 스펙 나열만으로는 쓸모없다.

## 2-1. `91. 질문지.md` 운용 방식 (2026-08-12 확인: 취소선 남기지 말고 완전 삭제)

취소선(~~답변~~) 처리 후 항목을 남겨두는 방식은 파일이 지저분해져 사용자가 불편해함 —
**답변 완료 항목은 취소선 없이 파일에서 완전히 제거**하고, 반영 내용만 해당 파일(README·
결정로그·운영기록 등)에 옮긴다. 남기는 건 오직 "아직 안 채워진 질문"뿐.


이 볼트는 `91. 질문지.md`를 상시 열린 질의응답 파일로 쓴다. 매 세션 시작 시 이 파일을 열어라.

- 사용자는 이 파일에 **직접 답을 적어 저장**한다 (채팅으로 다시 주지 않을 수도 있음 — 파일
  자체를 확인해야 함).
- 답이 채워진 항목: 해당 내용을 `01. README.md` / `02. 결정로그.md` / `03. 트러블슈팅.md` /
  `04. 운영기록.md` 등 적절한 파일에 반영하고, **질문지에서 그 항목을 삭제**한다.
- 답이 비어 있거나 "보류"인 항목: **삭제하지 말고 그대로 둔다.** 이게 곧 "아직 안 채워진 것
  목록" 역할을 한다.
- 새로 필요한 질문이 생기면 이 파일에 이어서 추가한다.

## 3. 사용자가 정보를 덤프했을 때 처리 절차

1. 그대로 `1. 로그/{오늘날짜}.md`에 **날것으로** 넣는다 (정제 금지)
2. 거기서 건져 분배한다
   - 판단/선택 → `02. 결정로그.md` (**버린 대안 반드시 물어라**)
   - 문제 해결 → `03. 트러블슈팅.md`
   - PM 활동(팀·예산·공모전·일정) → `04. 운영기록.md`
   - 현재 사실 → `01. README.md`
3. **수치와 날짜가 빠진 항목은 반드시 되물어라.** 나중에 복구 불가능하고, 자소서는 숫자 없으면 힘이 없다.
4. 불확실하면 추측하지 말고 "미확정"으로 표시하거나 확인받는다.
