# 08. 남은과제 — 지금 안 끝난 것 전부 한 장에

**덮어쓰는 파일.** 끝난 항목은 지우고, 새로 생긴 건 해당 절에 추가한다. 히스토리는 남기지 않는다
(끝난 경위는 [[02. 결정로그]]·[[1. 로그]]에).

**[[91. 질문지]]와의 역할 구분** — 질문지는 *"사용자가 답해야 풀리는 것"*만 담는다.
이 파일은 *"해야 할 일 전체"*(직접 작업·시험·서류 포함)를 담고, 질문으로 풀리는 항목은
여기에 요약만 두고 `Q번호`로 질문지를 가리킨다. **두 파일이 어긋나면 질문지가 정본이다.**

체크박스·진행률(%)을 쓰지 않는 건 규약 §4 때문이다. 대신 **"언제 풀리는가"**로 묶었다.

  경위는 [[03. 트러블슈팅]] 2026-08-21 밤 항목. 남은 건 count/rev·count/m 등 **스케일 실측**뿐

  **전압분배 회로 없이 STM32 ADC에 배터리 직결 금지.** ([[2. 하드웨어/04. 전원]])
- 카메라 장착 위치 → Q15 (모델·인터페이스·해상도·렌즈 후보는 확정)
- 모듈 경계 / 교체 방법 → Q4, Q5 (아이디어 단계, 추가 실물 개발은 안 하기로 함)
- 하드웨어 아키텍처·센서·전원·배선 문서는 현재 설계와 연결 상태를 반영했다. 이후 실물 배선과
  보정 결과가 나오면 각 문서의 ‘남은 검증’을 갱신한다.

## 7. 제출 서류

### 지금 정해야 하는 것 (서류 착수 전제)
- **한이음 제작설계서 유형** — 사용자가 제공한 `응용하드웨어` 서식으로 확정
- **한이음 시상 유형** — 창의도전형 / 학점연계형(사회공헌·여성참여) 중 택1 → Q8
- **두 보고서 작성 분담** — 본인 단독인지 팀 분담인지 → Q6
- **한이음 영상** — 해운물류 제출본의 소스는 재사용하되 1분 30초 규정과 한이음 평가축에 맞춰 별도 편집

### 작성 시 반드시 지킬 것
- **한이음은 블라인드** — 전 서류에 팀원 실명·학교명 기재 금지, "팀원1, 팀원2"로 표기
- **진도율(%)** — 한이음 개발보고서 필수 기재. 사용자가 최종 시험 직전까지는 제외하고,
  남은 이틀의 개발·검증 결과를 본 뒤 작성하기로 했다. 100% 미만이면 완성 예정일까지 기재한다.
- 글씨크기 제목14/내용12/표10, 글꼴 변경 금지 (양쪽 공통)
- 강조점 분리 — **해운물류는 항만·사일로 현장 서사**, **한이음은 기술 난이도·개발 과정**
- 표기 통일 — "Orin = 영상처리 서버", "대시보드 = 관제 콘솔". [[01. README]] 시스템 구성 절 참조
- 예산표의 NUCLEO 용도 "RTOS 실시간성 확보용"을 그대로 옮기지 말 것 (실제는 베어메탈)
- 모듈화를 "구현됨"처럼 쓰지 말 것 — 아이디어 단계 ([[02. 결정로그]])
- GitHub 주소는 한이음 2·3차 평가 대상자만 제출. 4개 레포 전부 push 완료 상태
  (`SiloRobot/stm32-controller`·`rpi4-dashboard`·`jetson-nano-b01`·`jetson-orin-nano`)

  사무국 확인 권장 ([[07. 제출요건]])

## 8. 시연 임박 시

- 영상 마지막 구간은 기구 조립·관제·구동·안전정지의 실제 성과 몽타주를 우선한다. 후속 계획은
  `전장 통합·실측 보정·철판 부착시험·AI 실시간 연동` 한 줄로 제한한다.

- 해운물류 2분 시연영상은 [[5. 보고서/03. 해운물류 시연영상 콘티]] 기준으로 촬영·편집
- RPi4 앱 자동 실행 전환 — 코드는 준비됨. 장치에서 build 후 `bash scripts/install-autostart.sh` 1회 실행
- 현장 네트워크 — 폐쇄망 대비 휴대폰 핫스팟 우선, 안 되면 이동식 라우터(2~3만원대) 구매
- Tailscale은 코디네이션 서버 접근만 되면 동작
